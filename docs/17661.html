Overview

# TwinWorld Challenge 2026 **TwinWorld Challenge 2026** 是 **ECCV 2026**（2026年9月8日，瑞典马尔默）上 [TwinWorld Workshop](https://twin-world.github.io/) 的官方挑战赛。 ## 挑战任务 **大规模3D语义高斯泼溅重建** 该挑战赛针对两个数据集上的大规模无人机影像和语义神经重建：**TUM**（TUM2TWIN）和**黄金海岸**。参赛者需要完成以下任务： 1. **新视角合成** — 从提供的相机位姿渲染逼真的RGB图像（所有场景）。 2. **3D几何重建** — 重建场景的3D点云（在TUM场景上进行评估）。 3. **3D语义分割** — 为重建点云的每个点分配5个语义类别标签之一（地面、墙壁、屋顶、窗户、其他）（在黄金海岸场景上进行评估）。 ## 时间表 | 里程碑 | 日期 | |-------|------| | 开发阶段开始 | 2026年8月4日 | | 最终阶段开始 | 2026年8月20日 | | 最终阶段截止 | 2026年9月1日 | | 研讨会成果展示 | 2026年9月8日 | ## 研讨会 挑战赛结果将在 **TwinWorld @ ECCV 2026** 研讨会（2026年9月8日 09:30）上展示。 该研讨会重点关注可扩展3D和4D场景理解、多模态重建、语义场景图，以及用于自动驾驶、施工监测和机器人技术的现实数字孪生应用。 ## 挑战赛组织者 Olaf Wysocki; Qilin Zhang; Chenghao Qian 请访问 [TwinWorld网站](https://twin-world.github.io/) 查看剑桥大学CV4DT全部组织委员会成员。

Evaluation

# 评估 ## 提交格式 参赛者需提交一个 **zip 文件**，结构如下（直接压缩数据集文件夹，不包含额外的顶层文件夹）： ``` submission.zip ├── tum/ │ └── <scene_id>/ │ ├── rgb/ │ │ ├── <frame_id>.png # 渲染的新视图，每个参考帧一张 │ │ └── ... │ └── 3D_point_cloud/ │ └── point_cloud.ply # x, y, z (float) └── gold_coast/ └── <scene_id>/ ├── rgb/ │ └── <frame_id>.png └── 3D_point_cloud/ └── point_cloud.ply # x, y, z (float) + classification (uchar) ``` - `rgb/` — 渲染的图像，**PNG 格式**，分辨率和帧 ID（文件名）必须与每个场景提供的参考帧完全相同。 - `3D_point_cloud/point_cloud.ply` — 重建的点云。`x, y, z` 始终需要。`classification` 属性（整数，为下面的 5 个类索引之一或 255 = 忽略）**仅对 Gold Coast 场景需要**。 - 场景 ID 和帧 ID 必须**完全匹配**起始工具包中的内容。提交缺少任何必需文件的结果将被拒绝，不计入评分（`incomplete_submission`）。 ## 语义类别（Gold Coast） | 索引 | 类别 | |------|------| | 0 | 地面 | | 1 | 墙壁 | | 2 | 屋顶 | | 3 | 窗户 | | 4 | 其他 | | 255 | 忽略（排除在评分外） | ## 指标 **2D 渲染（所有场景）：** | 指标 | 描述 | 方向 | |------|------|------| | **PSNR** | 渲染 RGB 图像的峰值信噪比 | ↑ | | **SSIM** | 结构相似度指数（Wang 等人，高斯加权） | ↑ | | **LPIPS** | 学习感知图像块相似度（VGG） | ↓ | **3D 几何（仅 TUM 场景）：** 真实值点云和提交的点云都裁剪到真实值边界框（+20 厘米填充）并以 2 厘米体素下采样；然后计算精确度/召回率 **F-分数（5 厘米、10 厘米、20 厘米）**。报告的 `F-score` 是三个值的平均值。 **3D 语义（仅 Gold Coast 场景）：** 每个真实值点取最近的提交点（10 厘米内）的标签；未匹配的点计为错误。按类别计算 IoU 并在所有场景上汇总；**mIoU 3D** 是 5 个类别的平均值。 ## 最终分数与排名 排行榜按 **Final Score**（最终分数）降序排列： ``` rendering_score = mean(PSNR / 50 上限为 1, SSIM, 1 − LPIPS) # 范围 [0, 1] geometry_score = mean(F-score @ 5 cm, 10 cm, 20 cm) # 范围 [0, 1] semantic_score = mIoU 3D # 范围 [0, 1] Final Score = rendering_score + geometry_score + semantic_score # 范围 [0, 3] ``` 分数越高越好；最高最终分数为 **3.0**。

Data

# 数据 ## 数据集 本赛事使用两个大规模无人机影像数据集： - **TUM** ([TUM2TWIN](https://tum2t.win/)) — 城市场景；评估指标为 **2D渲染 + 3D几何**。 - **黄金海岸** ([GT-LOD3基准](https://github.com/gdslab/GT-LOD3-Benchmark)、[黄金海岸子集](https://stac.d2s.org/collections/ee10a5c0-2554-44e5-b59f-81eedfe02eb6?.language=en)) — 沿海城市场景；评估指标为 **2D渲染 + 3D语义分割**（5个类别）。 完整数据集访问详情通过 [TwinWorld数据集网站](https://huggingface.co/datasets/Zqlin/TwinWorld_Datasets) 发布。 ## 开始工具包 [开始工具包](https://huggingface.co/datasets/Zqlin/TwinWorld_Datasets/tree/main/starting_kit) 包含在Hugging Face的数据集中，路径为 `starting_kit/`。其中包括： - `README.md` — 提交格式说明，以及可作为起点的一组参考高斯喷溅实现。 - `make_dummy_submission.py` — 用于生成结构正确的（随机内容）提交zip文件的脚本，用于流程测试 ## 提交格式 单个 **zip文件**，在顶层包含数据集文件夹： ``` submission.zip ├── tum/<scene_id>/ │ ├── rgb/<frame_id>.png │ └── 3D_point_cloud/point_cloud.ply # x, y, z └── gold_coast/<scene_id>/ ├── rgb/<frame_id>.png └── 3D_point_cloud/point_cloud.ply # x, y, z, classification ``` - 场景ID和帧ID（文件名主干）必须 **完全匹配** 各阶段提供的参考帧。 - `rgb/` 图像必须为PNG格式且分辨率 **完全匹配** 参考分辨率。 - 点云必须为有效的PLY格式，包含有限的 `x, y, z` 坐标。建议使用二进制小端序PLY格式，坐标采用 `float32` 以减小上传体积；仅存储上述属性（不包含颜色/法线——评分器会忽略这些属性且会增加上传体积）。 - 黄金海岸点云另需包含整数型 `classification` 属性，值范围为 {0, 1, 2, 3, 4, 255}。 ## 语义类别 5个评估类别：`0 地面, 1 墙体, 2 屋顶, 3 窗户, 4 其他`；`255` = 忽略（在评分中排除）。
