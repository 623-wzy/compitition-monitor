饮食质量：HEI-FG **HEI-FG** 是 **Healthy Eating Index-2020（健康饮食指数-2020）** 的食物组部分，是由 USDA/NCI 制定的指数，用于衡量食物选择在多大程度上遵循膳食指南。HEI 对食物组按**每 1,000 千卡的密度**进行评分。餐食的分数取决于其组成，而非份量大小，因此可应用于单餐。 | 组成部分 | 最高分数 | 满分标准（每 1,000 千卡） | |---|---:|---| | 总水果 | 5 | ≥ 0.8 cup-eq（杯当量） | | 完整水果 | 5 | ≥ 0.4 cup-eq | | 总蔬菜 | 5 | ≥ 1.1 cup-eq | | 深色蔬菜和豆类 | 5 | ≥ 0.2 cup-eq | | 全谷物 | 10 | ≥ 1.5 oz-eq（盎司当量） | | 乳制品 | 10 | ≥ 1.3 cup-eq | | 总蛋白质食物 | 5 | ≥ 2.5 oz-eq | | 海鲜和植物蛋白 | 5 | ≥ 0.8 oz-eq | | 精制谷物（限制） | 10 | ≤ 1.8 oz-eq（≥ 4.3 时得 0 分） | 分数在标准之间呈线性变化，HEI-FG = 100 × 分数 / 60。四个 HEI 营养素组成部分（添加糖、钠、饱和脂肪、脂肪酸比例）被省略，因为标签中没有这些数据。低于 100 千卡的餐食无分数，且在排行榜上不予计分。 克数依据 USDA 食物模式当量数据库通过固定系数转换为杯和盎司当量（例如，水果 150 克，生叶类蔬菜 60 克，熟米饭或面食 80 克每 oz-eq，肉类 28 克每 oz-eq）。常见的复合菜肴（如披萨和凯撒沙拉）按固定配方拆分。所有逻辑均在 `diet_quality.py` 中，因此你可以根据自己的任务 1 输出计算 HEI-FG：`hei_fg([(name, food_group, grams), ...], kcal)`。使用评估器的映射器（`group_mapper.py`）获取配料名称对应的食物组。 ## # 评估与提交格式 ## 一个文件，每餐一行 填写 `validation_template.csv`：974份验证餐食每餐一行。 将其压缩并上传压缩包（`zip submission.zip predictions.csv`）。文件名 无关紧要，但压缩包必须恰好包含一个CSV文件。 ``` meal_id,source,ingredients,carb_g,protein_g,hei_fg VAL-0001,january,"{""white rice"": 180, ""grilled chicken breast"": 120, ""steamed broccoli"": 80}",,41.5, VAL-0002,n5k,"{""margherita pizza"": 150}",,12.0, ``` | 列 | 任务 | 填写内容 | |---|---|---| | `ingredients` | 任务1 | 一个字典，内容为**自由文本食材名称 → 估计克数**，JSON格式（`{"rice": 150, "chicken": 100}`）。空盘填写 `{}`。 | | `carb_g` | 任务2 | 碳水化合物（克） | | `protein_g` | 任务2 | 蛋白质（克） | | `hei_fg` | 任务2 | HEI-FG饮食质量评分，0–100（见**数据**） | 填写 `ingredients` 和**您小组的任务2对应列**；其他列留空。 留空表示"未提交"。填写的列必须为每餐都提供数值。数字必须 ≥ 0。 使用pandas时，用 `json.dumps(...)` 写入字典并用 `to_csv` 保存可生成正确的引号。 ## 任务1评分 您只需提供名称和克数。评估器完成其余工作： | 列 | 定义 | |---|---| | **食物组F1** | 评估器将您的每个食材名称映射到课程食物组（见下文）。对每餐比较真实食物组集合与您的集合：F1 = 2·TP / (2·TP + FN + FP)。取每餐平均值。越高越好。 | | **食材F1** | 对食材本身进行相同计算，不分组：您的每个名称最多匹配一个真实食材。越高越好。 | | 遗漏/虚构 | 所有餐食总计：您未列出的真实食材（FN），以及您列出但餐食中不存在的食材（FP） | | 未映射名称 | 评估器无法归入食物组的您的名称数量。这些不计入食物组F1（无加分，无惩罚），但仍计入食材F1。 | | **总重量wMAPE** | 100 × Σ\|M − M̂\| / Σ M，其中M为餐食总重量（克数之和）。越低越好。 | | 重量MAE/偏差 | 平均 \|M − M̂\| 和平均 (M̂ − M)，单位为克 | | 已匹配食材wMAPE | 您正确识别的食材的克数误差 | ### 名称如何匹配到真实食材（食材F1） 1. **规范化。** 名称转为小写，复数变单数，统一常见同义词（"aubergine" = "eggplant"，"scallion" = "green onion"，"yam" = "sweet potato"）。去除制备和切割词汇（"grilled"、"sliced"、"breast"、"fillet"）。保留改变食物的词汇（"fried rice"、"brown rice"、"sweet potato"）。 2. **匹配。** 两个名称相等则匹配，或若一方包含另一方的所有词汇且共享主要食物词汇则匹配（"rice" = "white rice"，"chicken" = "grilled chicken breast"）。产生不同食物的修饰词会阻止匹配（"peanut butter" ≠ "butter"，"almond milk" ≠ "milk"）。 3. **通用名称和拼写错误。** 通用名称匹配其涵盖的具体食物（"berries" = "strawberries"，"herbs" = "parsley"，"fish" = "salmon"）。允许轻微拼写错误（"brocoli"）。 4. **一对一。** 每餐内，每个真实食材只能匹配一次。 ### 名称如何映射到食物组（食物组F1） 1. 若名称（规范化后）出现在 `ground_truth_names.csv` 中，使用其所属组。 2. 否则应用课程分类法的关键词规则（例如，含"chicken"的名称 → 禽肉，"lentil" → 豆类_大豆）。 3. 否则尝试用上述匹配规则对照已知名称。 4. 否则该名称为"未映射"。 在保留名称上，此映射与人工整理的真实值一致率达99.98%。 代码位于起始工具包的 `matching.py`、`group_mapper.py` 和 `taxonomy.py` 中。 ## Rules

1. **不得使用验证集标签。** 两个源数据集均为公开数据。禁止从原始发布版本或其他任何地方查找、匹配或检索验证照片或其标签。 2. **模型。** 允许使用 Google AI Studio 免费版的 Gemini、开源权重视觉-语言模型（例如 Gemma 3、Qwen-VL）以及在训练集上训练的任何方法。报告必须注明模型名称、版本及调用日期。 3. **每组一个账号。** 仅可使用本组账号提交。 4. **可复现性。** 你的 GitHub 仓库必须能复现排行榜结果：包括脚本及缓存的模型输出。 5. **数据使用。** 数据仅限用于本课程，并须引用 Nutrition5k 和 January Food Benchmark。
