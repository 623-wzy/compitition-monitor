Evaluation & Submission

# 评估与提交 本页介绍如何格式化提交内容以及条目的评分方式。有关任务、数据集和时间表，请参阅"概览"选项卡。 ## 构建预测 为每个评估帧生成一个检测文件，文件名以该帧的id命名。您需要预测的帧id列在起始工具包中（开发集使用`validation_frames.txt`，最终测试使用`test_frames.txt`）。每一行是一个检测，包含九个字段： ``` # cls cx cy cz dx dy dz yaw score 1 12.34 -3.21 0.05 4.10 1.92 1.55 1.5708 0.97 ``` * `cls` ∈ {1=车辆, 2=自行车, 3=行人} * `cx cy cz`：边界框中心，单位为米，"顶部"自车坐标系 * `dx dy dz`：长、宽、高，单位为米 * `yaw`：航向角（绕+z轴旋转），单位为弧度 * `score`：置信度 ∈ [0, 1]（用于排序检测） 将各帧文件压缩到存档根目录并在"提交"选项卡中上传。起始工具包中的`SUBMISSION_FORMAT.md`是权威规范，包含示例提交和格式检查器。上传前运行检查器。 ## 评估 我们完全遵循官方Mixed Signals / OpenCOOD评估协议，因此排行榜数据可直接与数据集论文进行比较。 ### 指标 * 匹配：预测框与真实框之间的鸟瞰图（BEV）旋转框交并比（IoU）（不使用z/高度维度用于匹配，与数据集基准一致）。 * 平均精度（AP）：VOC-2010"全点"插值法，精确率-召回率曲线下的面积（非11点变体）。 * 各类别：AP在IoU阈值0.3、0.5和0.7处分别针对车辆、自行车和行人独立计算。 * 匹配规则：在每一帧内，检测按置信度降序排列，并贪心地与真实框匹配。每个真实框最多只能匹配一次。不匹配的检测（或低于IoU阈值的匹配）为假正例。 * 评估范围：中心落在`x, y ∈ [-51.2, 51.2] m`范围外的边界框在评分前从预测和真实数据中排除。 ### 按mAP排名 排行榜按标题mAP排名，即论文中报告的三个各类别操作点的平均值： ``` mAP = mean( 车辆 AP@0.5 , 自行车 AP@0.5 , 行人 AP@0.3 ) ``` （行人使用较宽松的0.3 IoU评分，因为其边界框较小。）排行榜还报告车辆和自行车在IoU 0.5/0.7处的AP以及行人在IoU 0.3/0.5处的AP，与已发表的表格一致，但仅mAP决定排名。mAP的平局按排行榜列从左到右打破（从车辆AP@0.5开始），再按提交时间打破，因此较早的提交排名较高。 ### 评分程序 评分程序是开源的，可从"提交/文件"区域下载。它仅依赖`numpy`，从零开始实现BEV IoU和VOC AP，因此您可以在本地针对您自己的验证标签运行它，以精确再现排行榜分数。
