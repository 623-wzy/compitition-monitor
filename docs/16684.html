background:#fff8e6; padding:10px 14px; margin:0 0 18px;"> <strong>更新 —</strong> <strong>意向书截止日期延期至2026年8月15日</strong> (之前为7月25日)。所有其他日期保持不变。 </p> <p><em>2026年IEEE大数据杯的一个赛道，与<a href="https://bigdataieee.org/BigData2026/">IEEE国际大数据会议(IEEE BigData) 2026、美国亚利桑那州凤凰城</a>联合举办。</em></p> <p> 智能交通系统的路侧激光雷达感知受到大规模、标注完善的真实数据集成本高和稀缺性的限制。本挑战赛提出以下问题：是否可以使合成激光雷达数据足够逼真，使得在其上训练的深度学习模型能够泛化到真实激光雷达帧？ </p> <p> 为此，本挑战赛要求参赛者生成针对<strong>LUMPI</strong> 分布的合成激光雷达数据，在该数据上训练物体检测器，并在真实保留帧上提交检测结果。我们根据以下两项进行评分：(1)其合成帧与真实帧在分布上的接近程度，以及(2)仅在合成数据上训练的检测器在真实帧上的性能。 </p> <h2>重要日期</h2> <ul> <li><strong>意向书截止日期：</strong><strong>2026年8月15日</strong>(从7月25日延期)</li> <li><strong>最终报告和解决方案提交截止日期：</strong>2026年11月15日</li> <li><strong>获奖团队宣布：</strong>2026年11月25日</li> <li><strong>会议：</strong>2026年12月14-17日</li> </ul> <h2>参赛者参考资源</h2> <p> 为支持希望获得完整文档起点的参赛者，我们公开提供一个完整的参考管道，涵盖合成方法、实证分析、现成可用的合成数据集，以及开源激光雷达数据处理和可视化软件。这些材料作为指导提供，不作为要求。 </p> <p> 合成管道在<a href="https://arxiv.org/pdf/2509.02903">《UrbanTwin: 为Sim2Real激光雷达感知和评估构建高保真数字孪生体》(arXiv预印本)</a>中进行了描述，更深入的实证分析(包括本挑战赛采用的分布真实性指标)见<a href="https://scholar.google.com/scholar?oi=bibs&amp;cluster=6844982498826808010&amp;btnI=1&amp;hl=en">《高保真数字孪生体在缩小激光雷达基础智能交通系统感知Sim2Real差距中的应用》(IEEE T-ITS, 2026)</a>。 </p> <p> 使用该管道生成的合成激光雷达数据集发表在<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">《UrbanTwin: 合成路侧激光雷达数据集》(IEEE OJ-ITS, 2026)</a>，可从<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">Harvard Dataverse</a>下载。每个数据集包含<strong>10K帧</strong>的标注，覆盖<strong>六个目标类别</strong>用于<strong>检测、跟踪和分割任务</strong>，并与此处使用的多类评估直接兼容；论文中的实证分析包括分布真实性指标和单类3D物体检测概念验证研究。对于端到端激光雷达处理，我们还提供<a href="https://ieeexplore.ieee.org/document/11498694">《LiGuard框架》(IEEE T-IV, 2026)</a>

Evaluation

<h1>评估协议</h1> <p> 计算两个分数并将其合并为单个<em>综合</em>分数，该分数决定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合步骤：</p> <ol> <li>将50个提交的合成帧连接成一个集合<code>S_syn</code>；将50个保留的真实参考帧连接成<code>S_real</code>。</li> <li>将两者掩码到点云范围<code>[-40, -40, -5, 40, 40, 5]</code>。</li> <li>使用种子1234进行均匀随机下采样至<strong>N = 10,000个点</strong>（每侧），使用与启动工具包中本地评估器相同的种子。</li> <li>计算跨整个10,000点集合的<strong>一个</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离（CD）</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻成本；对称的。越低越好。</p> <h3>1b. 最大均值差异（MMD）</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计量（非对角线）。带宽<code>γ</code>通过1,000点联合子样本的中位数启发式设置（<code>γ = 1 / (2 · median ||x - y||²)</code>），以确保核函数在激光雷达空间尺度上不饱和。越低越好。 </p> <h3>1c. 地球移动距离（EMD）</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> Wasserstein-1，欧氏基本成本，通过网络单纯形精确求解（POT的<code>ot.emd2</code>）。以米为单位报告。越低越好。 </p> <h3>1d. 频歇点云距离（FPD）</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> FID风格：为每个集合的点拟合3元高斯分布，计算高斯之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 3D对象检测</h2> <p> 参与者在50个真实激光雷达帧上提交检测结果（<code>predictions.json</code>，其中ground truth被保留）。我们计算<strong>为此赛道定义的8个对象类别</strong>（<em>行人、汽车、自行车、摩托车、公交车、货车、货运车、未知</em>）的平均精度，IoU阈值为0.5（主要）和0.7（次要）。报告每个类别的AP，<strong>跨类别的平均AP（mAP）</strong>是排行榜的检测分数；held-out集合中zero ground-truth实例的类别被排除在平均值之外。报告KITTI 11点和40点插值AP；40点形式是排行榜主要指标。 </p> <p> Ground-truth和预测框使用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个有向BEV矩形的3D交集比与Z重叠的乘积。不应用KITTI截断/遮挡/最小高度难度过滤器，因为这些取决于2D边界框注释，这对路边激光雷达数据集不是自然的。 </p> <p>此赛道的有效类别字符串列在<code>config.json</code>中（随附于<code>reference_data/</code>）以及启动工具包中的<code>submission_format.md</code>中。任何具有无法识别的类别标签的预测都将被丢弃。</p> <h2>3. 综合分数</h2> <p>每个组成部分使用每赛道的归一化范围进行最小-最大归一化至[0, 1]：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 → 1 - 截断) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 → 截断) score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 归一化端点在<code>config.json</code>中公开（随附于<code>reference_data/</code>），因此本地评估器和服务器comp </p>

Data

<h1>数据</h1> <h2>LUMPI</h2> <p> 真实的<strong>LUMPI</strong>数据可从其原始发布源公开获取。我们不重新分发该数据。参与者必须直接从其源获取真实数据集，并遵守相应许可证。 </p> <ul> <li><strong>数据源：</strong> <a href="https://data.uni-hannover.de/dataset/lumpi">https://data.uni-hannover.de/dataset/lumpi</a></li> <li><strong>许可证：</strong>见数据源。</li> </ul> <h2>为参与者发布的资源</h2> <p>起始工具包（文件选项卡 → starting_kit）包含：</p> <ul> <li><code>detection_test_frames/</code> — <strong>50个真实激光雷达帧</strong>（仅点云数据，无标签），您必须在这些帧上运行检测器并提交预测结果。</li> <li><code>detection_test_frame_ids.json</code> — 您的<code>predictions.json</code>必须按顺序覆盖的规范帧ID列表。</li> <li><code>forbidden_frames.txt</code> — <strong>100个帧ID，您不得在其上进行训练、验证或超参数调整</strong>。这是50个检测测试帧和50个真实性参考帧的并集。遵守荣誉制度，通过您提交中的签署声明强制执行。</li> <li><code>local_eval.py</code> — 发送给Codabench工作节点的精确评分程序。在本地运行以从发布的检测测试帧生成的虚拟参考集重现服务器分数（逐位精确）。</li> <li><code>make_dummy_submission.py</code> — 生成一个已知不良的提交，用于测试格式。对于检查您的管道很有用。</li> <li><code>submission_format.md</code> — 完整的提交规范。</li> </ul> <h2>保留数据（仅组织者）</h2> <ul> <li>用作真实性参考集的50个真实帧。</li> <li>50个检测测试帧的真值框。</li> </ul> <h2>评估类别</h2> <p> 本赛道基于为<strong>LUMPI</strong>数据集定义的<strong>8</strong>个对象类别进行评分： <em>行人、汽车、自行车、摩托车、公交车、卡车、货车、未知</em>。排行榜的检测分数是这些类别的平均AP；在保留的50帧集中没有真值实例的类别从平均值中排除。 </p> <h2>数据划分</h2> <p> 划分是使用固定种子1234的分层随机样本。确切的帧ID列表在起始工具包中发布，因此任何人都可以从发布的真实数据集中复现它们。 </p> <h2>参考基准</h2> <p> 下面的数字仅针对<em>汽车</em>类别报告，取自该数据集的先前工作。排行榜的检测分数是本赛道定义的所有类别的平均AP（见<strong>评估</strong>），因此提交的评分覆盖范围比这些单类别参考更广。包含基准是为了证明仿真→真实迁移在该基准上是可实现的，并在您迭代时提供每类参考点以便定向。 </p> <table border="1" cellpadding="6"> <tr> <th>系统</th><th>汽车3D AP @ 0.5</th><th>汽车3D AP @ 0.7</th> </tr> <tr> <td>SEED（真实LUMPI训练，IEEE T-ITS 2026）</td> <td>0.4270</td> <td>未报告</td> </tr> <tr> <td>SEED（UT-LUMPI合成 → 真实LUMPI，IEEE T-ITS 2026）</td> <td>0.4474</td> <td>未报告</td> </tr> </table>

Submission

<h1>提交格式</h1> <p>将下面的所有内容打包到单个 <code>submission.zip</code> 文件中，并在<em>提交</em>选项卡上上传。</p> <pre> submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好50个文件 ├── predictions.json └── declaration.pdf # 签署的荣誉声明（PDF）。也接受 declaration.txt </pre> <h2>synthetic/&lt;id&gt;.bin</h2> <ul> <li>恰好 <strong>50</strong> 个文件。</li> <li>每个文件为原始 <code>float32</code> 数据，形状为 <code>N × 3</code>，按行主序存储，通道为 <code>(x, y, z)</code>，单位为米。</li> <li>接受 <code>N × 3</code> 或 <code>N × 4</code> 格式（xyz + 强度）；如果存在强度列，评分前将被删除。</li> <li>每个文件磁盘大小 ≤ 1.5 MB（约 125,000 个点）。真实性在数据集级别计算：将全部 50 帧连接、掩蔽到轨迹的点云范围、然后下采样至 10,000 个点（种子 1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会改进分数；帧顺序无关紧要。</li> <li>最简单的有效命名方式是 <code>0001.bin … 0050.bin</code>。</li> </ul> <h2>predictions.json</h2> <p>JSON 对象，其键为 <code>detection_test_frame_ids.json</code>（在启动工具包中）中的帧 ID。对于每个帧 ID，必须包含一个条目，即使该值是空列表。</p> <pre> { "&lt;frame_id_1&gt;": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "Car"}, {"box": [...], "score": 0.81, "class": "Person"} ], "&lt;frame_id_2&gt;": [], ... } </pre> <ul> <li><code>box</code>：7 个浮点数，遵循 OpenPCDet 约定。<code>(x, y, z)</code> 是 LiDAR 帧中的框<em>中心</em>（单位：米），<code>(dx, dy, dz)</code> 是沿框局部轴的完整尺度，<code>heading</code> 是绕 <code>+Z</code> 轴的旋转角度（单位：弧度）。</li> <li><code>score</code>：置信度，范围 [0, 1]。</li> <li><code>class</code>：该轨迹的有效类别字符串之一。有效值：<code>Person</code>、<code>Car</code>、<code>Bicycle</code>、<code>Motorcycle</code>、<code>Bus</code>、<code>Truck</code>、<code>Van</code>、<code>Unknown</code>。类别字符串不区分大小写匹配。计算 AP 前，带有无法识别的类别字符串的预测结果将被丢弃。</li> </ul> <h2>declaration.pdf（或 declaration.txt）</h2> <p>启动工具包包含 <code>declaration_template.pdf</code>，一份单页表单，预印了所需的荣誉声明和签名行。填写团队名称和日期，签署（使用任何 PDF 工具数字签署，或打印 → 签署 → 扫描），另存为 <code>declaration.pdf</code>，并将其包含在每次提交中。</p> <p>如果无法轻松生成签署的 PDF，也接受纯文本 <code>declaration.txt</code>。必需声明（原文，不区分大小写）：</p> <blockquote> <em>我确认我没有在 <code>forbidden_frames.txt</code> 中列出的任何帧上进行训练，且所有提交的检测结果都由仅在我生成的合成数据上训练的模型产生。</em> </blockquote> <h2>返回内容</h2> <p>评分后（有效提交通常需时 < 5 分钟），您将看到排行榜上的位置以及<em>详细结果</em>视图，其中包含所有组件指标，包括按类别的 AP。</p>

Rules

<h1>规则</h1> <h2>参赛资格</h2> <ul> <li>面向所有人开放——研究人员、学生、产业团队均可参赛。</li> <li>每个团队必须注册一个参赛者账户；不允许维护多个账户。</li> </ul> <h2>允许的做法</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理模型）。开源或闭源均可——重要的是合成数据。</li> <li>任何3D物体检测器架构，仅在您的合成数据上训练。</li> <li>检测器训练期间应用的增强方法（旋转、缩放、翻转、真值采样、噪声）——这些操作作用于合成数据，而非禁用的真实帧。</li> <li>使用公开真实数据集的训练集进行超参数选择或域适应，前提是不接触任何禁用帧。（禁用列表仅包含100个保留帧，不包括整个真实训练集。）</li> </ul> <h2>禁止的做法</h2> <ul> <li>对<code>forbidden_frames.txt</code>中列出的100个帧中的任何一个进行训练、验证、超参数调整或以其他方式观察真值。此禁令由署名声明强制执行，是本挑战赛的基础完整性规则。</li> <li>提交由在任何路边激光雷达数据集的真实标签上训练过的模型产生的预测结果。检测器必须仅基于仿真。</li> <li>通过Codabench排行榜信号逆向工程或推断隐藏的真实性参考帧（例如，设计用来泄露参考集身份的探测性提交）。发现从事此类活动的提交将被取消资格。</li> <li>多个账户、子团队账户或跨已注册团队协调。</li> </ul> <h2>取消资格</h2> <p> 组织者保留检查任何提交的合成帧和预测结果的权利，以寻找禁用帧泄露的证据（例如，与隐藏真实帧相似的合成帧；其分布暗示可访问隐藏真值的预测结果）。被取消资格的参赛者将从排行榜和奖励考虑中被移除。 </p> <h2>奖项</h2> <p>每条赛道：第1名500美元，第2名300美元，第3名200美元。赞助商信息将在开发阶段开始前公布。</p> <h2>发表和署名</h2> <ul> <li>每个参赛团队提交一份4–8页的挑战赛报告，描述其方法，截止日期为最终阶段截止日期（2026年11月15日）。</li> <li>倾向于不发表的团队可以选择加入其提交的非发表赛道。</li> <li>每条赛道的前3名团队受邀在凤凰城IEEE BigData 2026年会大数据杯研讨会分会场（2026年12月14–17日）进行展示，并通过挑战赛相关论文赛道向IEEE BigData 2026会议论文集提交全文论文。</li> <li>挑战赛组织者可发表所有提交的汇总分析（匿名处理，除非明确获得许可）。</li> </ul>
