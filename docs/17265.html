竞赛描述

This competition focuses on fine-grained understanding of urban-level building facade components, utilizing the City-Fac dataset. The data is collected by vehicle-mounted mobile laser scanning systems, covering multiple types of typical urban street blocks in Xiamen, with a cumulative road length of approximately 60 km. The dataset includes fine-grained building facade element annotations such as walls, windows, doors, roofs, billboards, air conditioning units, canopies, and balconies, with both semantic-level and instance-level labels provided. Participants need to identify independent building facade component instances in the test point cloud and output the corresponding semantic categories and instance numbers. The competition adopts a result submission mode. Participants complete model training and inference locally and only submit prediction results to Codabench, where the platform automatically scores using hidden instance labels.

# **Building Facade Point Cloud Semantic/Instance Segmentation** ## **Overview** This track uses the City-Facade dataset to conduct semantic segmentation and instance segmentation of building facade point clouds. Participants need to predict semantic categories for each point in the test set and further distinguish instance numbers of different building facade components within the same semantic category. The City-Facade dataset is collected by vehicle-mounted mobile laser scanning systems, covering 6 typical urban street scene categories in Xiamen City, with a total road length of approximately 60 km and containing approximately 200 million annotated points. Semantic categories are as follows: | **ID** | **English Category** | **Chinese Category** | | ------ | ------------------------- | -------------------- | | 0 | Background / Unclassified | Background/Unclassified | | 1 | Wall | Wall | | 2 | Window | Window | | 3 | Door | Door | | 4 | Roof | Roof | | 5 | Advertisement | Advertisement Board | | 6 | Air Conditioner | Air Conditioner Unit | | 7 | Rain Shed | Rain Shed | | 8 | Balcony | Balcony | Competition workflow: 1. Develop 3D point cloud semantic and instance segmentation models on the training dataset; 2. Use the trained model to predict test data; 3. Generate semantic labels and instance labels for each test point; 4. Compress prediction results according to the specified directory structure; 5. Upload results to Codabench; 6. The platform automatically evaluates and updates the leaderboard. Dataset project address: ```text https://github.com/gorgeouseping/City-Facade ``` ## **Evaluation** The main ranking metric is the comprehensive score: ```text Score = 0.5 × mIoU + 0.5 × AP50 ``` Where: - mIoU is used to evaluate semantic segmentation accuracy; - AP50 is used to evaluate instance segmentation accuracy. Auxiliary metrics include: - mIoU - OA - IoU for each category - AP - AP25 - AP50 All metrics are higher the better. Each team can submit a maximum of 5 times per day. If the comprehensive score is the same, it is recommended to determine rankings in order by AP50, mIoU, AP25, and submission time. ## **Submission Format** Participants must provide semantic labels and instance labels for each point in the test set and submit a ZIP compressed package. ```text submission.zip └── predictions/ ├── CAR/ │ ├── CAR-30-003_000000.txt │ ├── CAR-30-003_000001.txt │ └── ... ├── JMC/ ├── SGS/ └── ... ``` Directory names and prediction file names must be consistent with the test data. Each TXT file contains 6 fields: ```text X Y Z intensity semantic_label instance_id ``` Array dimensions are: ```text N × 6 ``` Where: - `N` is the number of points in the point cloud; - `X Y Z` are 3D coordinates; - `intensity` is laser intensity; - `semantic_label` is the predicted semantic category; - `instance_id` is the predicted instance number. Submitted files must satisfy: 1. The number and order of points are completely consistent with the original test files; 2. The 3D coordinates and intensity fields must not be modified; 3. Semantic category ID range is 0-8; 4. Instance IDs must be non-negative integers; 5. Different instances use different instance IDs; 6. Prediction file directories and file names must be consistent with the test set; 7. The ZIP root directory must contain a `predictions` folder. ## **Citation** When using the City-Facade dataset, please cite: ```bibtex @article{chen2026cityfacade, title={City-Facade: A city-level large-scale building facade point cloud dataset for semantic and instance segmentation}, author={Chen, Yiping and Li, Jonathan and Han, Ting and Feng, Huifang and Chen, Jun and Wang, Cheng}, journal={ISPRS Journal of Photogrammetry and Remote Sensing}, volume={232}, pages={675--688}, year={2026}, doi={10.1016/j.isprsjprs.2026.01.003} } ```
