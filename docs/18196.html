Evaluation

# 评估 协议和指标采用前一届UPAR挑战赛版本（WACV 2024）的标准。评分程序复现了原始评估脚本。 ## 评估内容 对于每个查询，你的模型需要返回整个库集的排名，最佳匹配排在首位。如果库集图像的所有40个属性都与查询相等，则该图像是查询的正确匹配。 ## 指标 | 排行榜 | 含义 | | --- | --- | | **mADM** | 平均匹配度 - **排名指标** | | mAP | 查询的平均精度均值 | | Rank-1 | 最高排名结果是正确匹配的查询占比 | | Rank-5 | 前5个结果中包含正确匹配的查询占比 | | Rank-10 | 前10个结果中包含正确匹配的查询占比 | | mINP | 平均逆负惩罚 | 对于一个查询，库集中有`R`个正确匹配，其排名为`r_1 < r_2 < ... < r_R`： ```text AP = ( 1/r_1 + 2/r_2 + ... + R/r_R ) / R INP = R / r_R ``` `AP`奖励**所有**正确匹配都排在前面的情况。`INP`仅关注最难找到的匹配：如果最后一个正确匹配紧接在其他匹配之后则为1，搜索深度越深则数值越接近0。`mAP`和`mINP`是所有查询的均值，`Rank-k`是`r_1 <= k`的查询占比。 ### mADM - 排名指标 `AP`是全有或全无的：与查询相差一个属性的图像与相差二十个属性的图像计数完全相同。**平均匹配度**（ADM）保持`AP`的结构但对接近匹配进行评分。 对于一个查询，库集图像的匹配度是该图像与查询相同的40个属性的占比。它按查询进行归一化，使得平均库集图像获得0分，完美匹配获得1分： ```text dom(g) = (图像g与查询相同的属性数) / 40 ndom(g) = max( 0, (dom(g) - 平均dom) / (最大dom - 平均dom) ) 平均值、最大值取遍整个库集 ``` 对于排名`g_1, g_2, ...`和正确匹配的排名`r_1 < ... < r_R`： ```text ADM = ( 1/R ) * 对k求和 ( ndom(g_1) + ... + ndom(g_{r_k}) ) / r_k ``` 因此，在每个正确匹配的排名位置，`AP`问的是**到目前为止排名的图像中有多少比例是正确的**，而`ADM`问的是**到目前为止排名的图像平均匹配度如何**。将外观相似的人排在无关人员之前的排名得分更高，即使两者都在相同位置找到精确匹配也是如此。完美排名达到1分。`mADM`是所有查询的均值。 参考文献：A. Specker, J. Beyerer, *Balanced Pedestrian Attribute Recognition for Improved Attribute-based Person Retrieval*, 2023，以及UPAR挑战赛2024报告。 ## 平局 如果返回距离或相似性，相等值按库集顺序排名。避免大量平局组，它们会使结果依赖于该顺序。 ## 排行榜 排行榜显示的是你的**最新**提交，而非最佳提交。

# 提交 您上传一个zip文件，平台使用您未曾看过的数据对其进行测试。 ## Zip文件 压缩您提交文件夹的**内容**，而非文件夹本身： ```bash cd my_submission zip -r ../my_submission.zip . -x "*/__pycache__/*" "*.DS_Store" ".git/*" unzip -l ../my_submission.zip | head # run.py 必须在根目录 ``` 归档文件根目录需要的文件： ```text run.py 您的入口点 metadata.yaml 从示例提交中原样复制 <其他任何文件> 权重、模块、配置 ``` ## API 摄取程序导入 `run.py` 并调用： ```python def load_model() -> None: """可选。调用一次。在此处加载您的权重。""" def rank_gallery(sample: dict) -> dict: """调用一次，包含所有查询和整个库。""" ``` `sample` 结构为： ```python { "attribute_names": ["Age-Young", "Age-Adult", ...], # 40个名称，按顺序 "queries": [[0, 1, 0, 1, ...], ...], # Q个查询 x 40个值 (0/1) "gallery": [ # G个库图像 {"index": 0, "image": "<dataset>/images/0.jpg", # images.csv中列出的路径 "image_path": "/app/input_data/images/<dataset>/images/0.jpg"}, # 绝对路径，可读 ... ], } ``` 返回一个字典，**恰好包含以下键之一**。每个键对应一个 `Q x G` 矩阵（列表嵌套、numpy数组或张量）：第 `i` 行对应 `queries[i]`，第 `j` 列对应 `gallery[j]`。 | 键 | 内容 | 排序方式 | | --- | --- | --- | | `"distances"` | 浮点数，图像 `j` 与查询 `i` 的距离 | 从小到大 | | `"similarities"` | 浮点数，图像 `j` 与查询 `i` 的匹配程度 | 从大到小 | | `"ranking"` | 整数，第 `i` 行 = 所有库索引 `0..G-1`，最佳匹配优先 | 按给定顺序 | 该键说明了您的值的方向，因此距离不会被误认为是得分。裸数组、NaN/Inf、错误形状或 `ranking` 行不是 `0..G-1` 的排列都会导致提交失败，并在摄取日志中显示错误信息。相等的距离或相似性按库顺序排名。 通常的做法分两步：预测每个库图像的属性概率（仅一次），然后计算每个查询到每个图像的距离。示例提交正是这样做的，无需构建 `Q x G x 40` 张量。 ## 运行时环境 - **无网络访问。** 在zip中包含您的权重。运行时不下载任何内容。 - 镜像为 `pytorch/pytorch:2.4.1-cuda12.1-cudnn9-runtime`：Python 3.11、torch 2.4.1、torchvision、numpy、Pillow。您的代码导入的任何其他内容必须包含在zip中。 - 整个运行有时间限制。`rank_gallery()` 是单次调用，因此请自行批量加载图像和推理，并打印您自己的进度：这会显示在摄取日志中。 - 工作目录是您的提交文件夹，因此相对路径指向您的权重是可行的。
