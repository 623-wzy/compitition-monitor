background:#fff8e6; padding:10px 14px; margin:0 0 18px;"> <strong>更新——</strong><strong>意向书截止日期延长至2026年8月15日</strong>（原定为7月25日）。其他所有日期保持不变。 </p> <p><em>2026年IEEE大数据杯的赛道之一，与<a href="https://bigdataieee.org/BigData2026/">IEEE国际大数据会议（IEEE BigData）2026</a>同期举行，地点：美国亚利桑那州凤凰城</em>。</p> <p> 智能交通系统的路侧激光雷达感知受限于大规模、高质量标注真实数据集的成本和稀缺性。本挑战赛提出的问题是：合成激光雷达数据能否达到足够的真实感，使得在其上训练的深度学习模型能够泛化到真实激光雷达帧？ </p> <p> 为此，本挑战赛要求参赛者生成针对<strong>V2X-Real</strong>分布的合成激光雷达数据，在该数据上训练目标检测器，并提交对真实预留帧的检测结果。评分标准包括：（1）其合成帧与真实帧的分布相似度，以及（2）纯仿真训练的检测器在真实帧上的表现。 </p> <h2>重要日期</h2> <ul> <li><strong>意向书截止日期：</strong><strong>2026年8月15日</strong>（从7月25日延长）</li> <li><strong>最终报告和解决方案提交截止日期：</strong>2026年11月15日</li> <li><strong>获胜队伍公布：</strong>2026年11月25日</li> <li><strong>会议：</strong>2026年12月14日至17日</li> </ul> <h2>参赛者参考资源</h2> <p> 为支持希望获得文档化起点的参赛者，我们公开发布完整的参考流程，涵盖合成方法、实证分析、即用型合成数据集以及开源激光雷达数据处理与可视化软件。这些材料仅作为指导，而非强制性要求。 </p> <p> 合成流程描述见<a href="https://arxiv.org/pdf/2509.02903">《UrbanTwin：构建用于Sim2Real激光雷达感知与评估的高保真数字孪生》（arXiv预印本）</a>，更深入的实证分析（包括本挑战赛采用的分布真实感指标）见<a href="https://scholar.google.com/scholar?oi=bibs&amp;cluster=6844982498826808010&amp;btnI=1&amp;hl=en">《用于弥合基于激光雷达的智能交通系统感知中Sim2Real差距的高保真数字孪生》（IEEE T-ITS，2026）</a>。 </p> <p> 使用该流程生成的合成激光雷达数据集发布于<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">《UrbanTwin：合成路侧激光雷达数据集》（IEEE OJ-ITS，2026）</a>，可在<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">Harvard Dataverse</a>下载。每个数据集包含<strong>10K帧</strong>，标注了<strong>六个目标类别</strong>，用于<strong>检测、跟踪和分割任务</strong>，与本赛事使用的多类别评估直接兼容；论文中的实证分析包括分布真实感指标和单类别3D目标检测研究作为概念验证。对于端到端激光雷达处理，我们还提供了<a href="https://ieeexplore.ieee.org/document/11498694">LiGuard框架（IEEE T-IV，2026）</a>

Evaluation

<h1>评估协议</h1> <p> 计算两个分数并合并为一个<em>综合</em>分数，以确定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合：</p> <ol> <li>将50个提交的合成帧拼接为一个集合<code>S_syn</code>；将50个保留的真实参考帧拼接为<code>S_real</code>。</li> <li>将两者掩码限制在点云范围<code>[-40, -40, -8, 40, 40, 2]</code>内。</li> <li>使用随机种子1234（与入门套件中本地评估器使用的种子相同）对每侧均匀随机子采样至<strong>N = 10,000点</strong>。</li> <li>在整个10,000点集上计算<strong>一次</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离（CD）</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻代价；对称。越低越好。</p> <h3>1b. 最大均值差异（MMD）</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计量（非对角）。带宽<code>γ</code>通过1,000点联合子样本的中位数启发式设置（<code>γ = 1 / (2 · 中位数 ||x - y||²)</code>），以确保核函数在LiDAR空间尺度上不饱和。越低越好。 </p> <h3>1c. 推土机距离（EMD）</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> 使用欧几里得地面成本的Wasserstein-1距离，通过网络单纯形法（POT的<code>ot.emd2</code>）精确求解。以米为单位报告。越低越好。 </p> <h3>1d. Fréchet点云距离（FPD）</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> 类FID风格：对每个集合的点拟合三元高斯分布，计算高斯分布之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 3D目标检测</h2> <p> 参与者对50个真实LiDAR帧提交检测结果（<code>predictions.json</code>），这些帧的真实标签被保留。我们在该赛道定义的<strong>3个目标类别</strong>（<em>车辆、行人、卡车</em>）上计算平均精度，IoU阈值分别为0.5（主要）和0.7（次要）。报告每类AP，<strong>跨类别的平均AP（mAP）</strong>作为排行榜的检测分数；在保留集中没有真实实例的类别不参与平均计算。报告KITTI 11点和40点插值AP两种形式；40点形式是排行榜的主要指标。 </p> <p> 真实标签和预测框使用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个定向BEV矩形之间的3D交并比乘以Z轴重叠率。不应用KITTI的截断/遮挡/最小高度难度过滤，因为这些依赖于2D边界框标注，而这对于路边LiDAR数据集并不自然。 </p> <p>该赛道的有效类别字符串列于<code>config.json</code>（位于<code>reference_data/</code>中）和入门套件的<code>submission_format.md</code>中。任何带有无法识别类别标签的预测将被丢弃。</p> <h2>3. 综合分数</h2> <p>每个分量使用按赛道归一化范围进行最小-最大归一化至[0, 1]：</p> <pre> score_realism = 均值( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) （越低越好 → 1 - 裁剪） score_detection = norm( AP_3d @ IoU 0.5 ) （越高越好 → 裁剪） score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 归一化端点在<code>config.json</code>中公开（位于<code>reference_data/</code>中），因此本地评估器和服务器计算出的分数相同。 </p> <h2>

Data

<h1>数据</h1> <h2>V2X-Real</h2> <p> 真实的<strong>V2X-Real</strong>数据已随其原始版本公开发布。我们不重新分发该数据。参赛者必须直接从其来源处获取真实数据集，并遵守其自身的许可协议。 </p> <ul> <li><strong>来源：</strong> <a href="https://github.com/ucla-mobility/V2X-Real">https://github.com/ucla-mobility/V2X-Real</a></li> <li><strong>许可协议：</strong> 见来源处。</li> </ul> <h2>向参赛者发布</h2> <p>起始工具包（<em>文件</em>标签页 &rarr; starting_kit）包含：</p> <ul> <li><code>detection_test_frames/</code> &mdash; <strong>50帧真实激光雷达数据</strong> （仅点云，无标注），您必须在这些数据上运行检测器并提交预测结果。</li> <li><code>detection_test_frame_ids.json</code> &mdash; 您的<code>predictions.json</code>必须按顺序覆盖的帧ID规范列表。</li> <li><code>forbidden_frames.txt</code> &mdash; <strong>100个禁止用于训练、验证或超参数调优的帧ID</strong>。这是50个检测测试帧与50个真实性参考帧的并集。诚信制度，通过您提交时的签署声明强制执行。</li> <li><code>local_eval.py</code> &mdash; 发送至Codabench工作节点的精确评分程序。在本地运行它以复现服务器分数（逐位一致），前提是您从发布的检测测试帧生成虚拟参考集。</li> <li><code>make_dummy_submission.py</code> &mdash; 生成一个已知的无效提交，用于测试格式。对检验您的流程完整性很有用。</li> <li><code>submission_format.md</code> &mdash; 完整的提交规范。</li> </ul> <h2>保留数据（仅组织者可用）</h2> <ul> <li>50帧真实数据用作<em>真实性参考集</em>。</li> <li>50个检测测试帧的真值框。</li> </ul> <h2>评估类别</h2> <p> 本赛道对<strong>V2X-Real</strong>数据集定义的<strong>3</strong>个目标类别进行评分： <em>vehicle（车辆）、pedestrian（行人）、truck（卡车）</em>。排行榜的检测分数是这些类别的平均AP；在保留的50帧数据集中真值实例为零的类别不计入平均值。 </p> <h2>数据划分</h2> <p> 数据划分为分层随机抽样，固定随机种子1234。精确的帧ID列表发布在起始工具包中，任何人都可以从发布的真实数据集复现这些划分。 </p> <h2>参考基线</h2> <p> 以下数字仅针对<em>Car（汽车）</em>类别报告，取自该数据集上的先前工作。排行榜的检测分数是本赛道定义的所有类别的平均AP（见<strong>评估</strong>部分），因此提交的作品将在比这些单类别参考更广泛的覆盖范围上评分。纳入这些基线是为了证明在此基准上仿真到真实迁移是可行的，并在您迭代过程中为方向提供逐类参考点。 </p> <table border="1" cellpadding="6"> <tr> <th>系统</th><th>Car 3D AP @ 0.5</th><th>Car 3D AP @ 0.7</th> </tr> <tr> <td>V2X-Real无融合基准（SECOND，真实数据）</td> <td>0.3556</td> <td>无报告</td> </tr> <tr> <td>SECOND（UT-V2X-Real合成数据 &rarr; V2X-Real-IC，IEEE T-ITS 2026）</td> <td>0.6318</td> <td>无报告</td> </tr> </table>

Submission

<h1>提交格式</h1> <p>将以下内容全部打包到单个 <code>submission.zip</code> 文件中，并在<em>提交</em>标签页上传。</p> <pre> submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好 50 个文件 ├── predictions.json └── declaration.pdf # 签署的诚信声明（PDF）。也接受 declaration.txt。 </pre> <h2>synthetic/&lt;id&gt;.bin</h2> <ul> <li>恰好 <strong>50</strong> 个文件。</li> <li>每个文件为原始 <code>float32</code> 格式，形状 <code>N &times; 3</code>，按行主序排列，通道为 <code>(x, y, z)</code>，单位为米。</li> <li>接受 <code>N &times; 3</code> 或 <code>N &times; 4</code>（xyz + 强度）格式；如果存在强度列，在评分前会被丢弃。</li> <li>每个文件在磁盘上不超过 1.5 MB（约 125,000 个点）。真实度在数据集层面计算：将 50 帧全部拼接，根据赛道的点云范围进行掩码，然后下采样至 10,000 个点（随机种子 1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会提高分数；帧的顺序无关紧要。</li> <li>最简单的有效命名为 <code>0001.bin … 0050.bin</code>。</li> </ul> <h2>predictions.json</h2> <p>JSON 对象，其键为 <code>detection_test_frame_ids.json</code>（在初始工具包中）中的帧 ID。对于每个帧 ID，都必须包含一个条目，即使值为空列表。</p> <pre> { "&lt;frame_id_1&gt;": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "vehicle"}, {"box": [...], "score": 0.81, "class": "pedestrian"} ], "&lt;frame_id_2&gt;": [], ... } </pre> <ul> <li><code>box</code>：7 个浮点数，遵循 OpenPCDet 约定。<code>(x, y, z)</code> 为框<em>中心</em>在激光雷达坐标系中的位置（单位：米），<code>(dx, dy, dz)</code> 为沿框局部轴的全尺寸，<code>heading</code> 为绕 <code>+Z</code> 轴的旋转（弧度）。</li> <li><code>score</code>：[0, 1] 范围内的置信度。</li> <li><code>class</code>：该赛道的有效类别字符串之一。有效值：<code>vehicle</code>、<code>pedestrian</code>、<code>truck</code>。类别字符串不区分大小写匹配。包含无法识别类别字符串的预测在计算 AP 前会被丢弃。</li> </ul> <h2>declaration.pdf（或 declaration.txt）</h2> <p>初始工具包提供 <code>declaration_template.pdf</code>，这是一张单页表格，预印了所需的诚信声明和签名栏。填写团队名称和日期，签名（可使用任何 PDF 工具进行数字签名，或打印 &rarr; 签名 &rarr; 扫描），保存为 <code>declaration.pdf</code>，并包含在每次提交中。</p> <p>如果您无法轻松生成带签名的 PDF，也接受纯文本 <code>declaration.txt</code>。所需声明（原文，不区分大小写）：</p> <blockquote> <em>我确认我未使用 forbidden_frames.txt 中列出的任何帧进行训练，且所有提交的检测结果均由仅基于我生成的合成数据训练的模型产生。</em> </blockquote> <h2>返回内容</h2> <p>评分后（有效提交通常少于 5 分钟），您将在排行榜上看到自己的位置，以及包含所有组件指标（包括每类 AP）的<em>详细结果</em>视图。</p>

Rules

<h1>规则</h1> <h2>参赛资格</h2> <ul> <li>面向所有人开放——研究人员、学生、企业团队。</li> <li>每个团队必须注册一个参赛账户；不得维护多个账户。</li> </ul> <h2>允许事项</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理）。开源或闭源均可——重要的是合成数据。</li> <li>任何3D目标检测器架构，仅使用<em>您的合成数据</em>进行训练。</li> <li>在检测器训练期间应用的数据增强（旋转、缩放、翻转、真值采样、噪声）——这些操作作用于合成数据，而非禁止使用的真实帧。</li> <li>使用公开真实数据集的<strong>训练划分（train split）</strong>进行超参数选择或领域自适应，<em>前提是不接触任何禁止帧</em>。（禁止列表仅包含100个保留帧，而非整个真实训练集。）</li> </ul> <h2>禁止事项</h2> <ul> <li>对<code>forbidden_frames.txt</code>中列出的100帧中的任何一帧进行训练、验证、超参数调优，或以其他方式观察其真值。此项通过签署声明强制执行，是挑战赛的基础完整性规则。</li> <li>提交由在<em>任意</em>路侧LiDAR数据集的真实标签上训练过的模型生成的预测结果。检测器必须仅使用仿真数据。</li> <li>通过Codabench排行榜信号逆向工程或推断保留的真实感参考帧（例如，旨在泄露参考集身份的探测性提交）。被发现存在此类行为的提交将被取消资格。</li> <li>注册多个账户、子团队账户，或跨注册团队协作。</li> </ul> <h2>取消资格</h2> <p> 组织者保留检查任何提交的合成帧和预测结果的权利，以查找禁止帧泄露的证据（例如，与保留的真实帧惊人相似的合成帧；其分布暗示可访问保留真值的预测）。被取消资格的参与者将从排行榜和奖项评选中移除。 </p> <h2>奖项</h2> <p>每个赛道：第一名500美元，第二名300美元，第三名200美元。赞助商将在开发阶段开始前公布。</p> <h2>发表与署名</h2> <ul> <li>每个参赛团队需提交一份<strong>4-8页的挑战赛报告</strong>，描述其方法，截止日期为最终阶段截止日期（2026年11月15日）。</li> <li>不希望发表的团队可选择将其提交纳入<em>非发表赛道</em>。</li> <li>每个赛道的前三名团队将被邀请在IEEE BigData 2026 Big Data Cup研讨会（2026年12月14-17日，亚利桑那州凤凰城）上展示，并可通过挑战赛关联的论文通道向IEEE BigData 2026会议论文集提交完整论文。</li> <li>挑战赛组织者可能会发表所有提交的汇总分析（除非获得明确许可，否则采用匿名形式）。</li> </ul>
