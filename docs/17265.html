竞赛描述

本比赛面向城市级建筑立面构件精细理解，采用City-Facade大规模三维点云数据集。 数据由车载移动激光扫描系统采集，覆盖厦门市多类典型城市街区，累计道路长度约60 km。数据包含墙面、窗户、门、屋顶、广告牌、空调外机、雨棚和阳台等细粒度建筑立面要素标注，并提供语义级与实例级标签。 参赛者需要识别测试点云中的独立建筑立面构件实例，并输出相应实例编号和语义类别。 比赛采用结果提交模式。参赛者在本地完成模型训练和推理，仅向Codabench提交预测结果，平台使用隐藏实例标签进行自动评分。

# **建筑物立面点云语义/实例分割** 各参赛队伍： 您好！ 为保障“第十届全国激光雷达大会——City-Facade 建筑立面点云实例分割大赛”的公平性与参赛结果的可信度，经大赛组委会讨论决定，现统一要求本赛道各参赛队伍提交与评估平台提交结果相对应的训练日志和推理日志，用于竞赛结果核验。具体要求如下： 一、提交材料 训练日志：提交用于生成相应预测结果的模型原始训练日志，包括训练时间、训练配置、训练轮次、损失变化及验证指标等已记录信息，并注明对应的基准模型。 推理日志：提交生成评估平台对应预测结果的原始推理日志，包括推理时间、结果信息等已记录内容。 对应关系说明：提供简要说明文件，注明队伍名称、平台账号、提交 ID、提交时间，以及榜单上提交记录对应的训练日志和推理日志。 二、提交方式及时间 请于**10月9日00:00**前，将上述材料打包为压缩文件，**以“队伍名称_训练与推理日志.zip”命名，并回复luoy583@mail2.sysu.edu.cn**提交。 请确保材料真实、完整，保留日志原始内容。如未进行训练，或部分日志未记录、未完整保存，请在说明文件中如实说明相关情况及原因。 三、核验安排 本次核验适用于本赛道全部参赛队伍，组委会将按照统一标准开展审核。对于需要进一步核实的内容，组委会将联系相关队伍补充材料或作出说明。请各队伍妥善保存相关代码、模型权重及预测结果，以便配合后续核验。 感谢各参赛队伍的理解与配合，共同维护公平、严谨的竞赛环境。 此致 敬礼！ 第十届全国激光雷达大会大赛组委会 City-Facade 建筑立面点云实例分割赛道 2026年10月8日 ## **Overview** 本赛道采用 City-Facade 城市建筑立面点云数据集，开展建筑立面点云语义分割与实例分割。 参赛者需要为测试集中的每个点预测语义类别，并进一步区分同一语义类别下不同建筑立面构件的实例编号。 City-Facade 数据由车载移动激光扫描系统采集，覆盖厦门市 6 类典型城市街区场景，累计道路长度约 60 km，包含约 2 亿个带标注点。 语义类别如下： | **编号** | **英文类别** | **中文类别** | | -------- | ------------------------- | ------------ | | 0 | Background / Unclassified | 背景或未分类 | | 1 | Wall | 墙面 | | 2 | Window | 窗户 | | 3 | Door | 门 | | 4 | Roof | 屋顶 | | 5 | Advertisement | 广告牌 | | 6 | Air Conditioner | 空调外机 | | 7 | Rain Shed | 雨棚 | | 8 | Balcony | 阳台 | 参赛流程： 1. 在训练数据集上开发三维点云语义分割与实例分割模型； 2. 使用训练完成的模型预测测试数据； 3. 为每个测试点生成语义标签和实例标签； 4. 按指定目录结构压缩预测结果； 5. 将结果上传至 Codabench； 6. 平台自动评测并更新排行榜。 数据集项目地址： ```text https://github.com/Ting-Devin-Han/City-Facade ``` ## **Evaluation** 主排名指标为综合得分： ```text Score = 0.5 × mIoU + 0.5 × AP50 ``` 其中： - mIoU 用于评价语义分割精度； - AP50 用于评价实例分割精度。 辅助指标包括： - mIoU - OA - 各类别 IoU - AP - AP25 - AP50 所有指标均为越高越好。 每支队伍每日最多提交 5 次。 若综合得分相同，依次按照 AP50、mIoU、AP25 和提交时间确定排名。 ## **Submission Format** 参赛者须为测试集中的每个点提供语义标签和实例标签，并提交一个 ZIP 压缩包。 压缩包根目录必须包含`predictions/`文件夹： ```text submission.zip └── predictions/ ├── CAR/ │ ├── CAR-30-003_000000.txt │ ├── CAR-30-003_000001.txt │ └── ... ├── JMC/ ├── SGS/ ├── XHR/ └── YWR/ ``` 目录名称和预测文件名称必须与测试数据保持一致。例如： ```text test/JMC/JMC-1-013_000000.txt predictions/JMC/JMC-1-013_000000.txt ``` 每个预测 `.txt` 文件为 `N x 7` 数组，字段顺序固定为： ```text X Y Z intensity instance_id semantic_label instance_score ``` 其中： - `N` 为点云点数； - `X Y Z` 为三维坐标； - `intensity` 为激光强度； - `instance_id` 为预测实例编号； - `semantic_label` 为预测语义类别； - `instance_score` 为预测实例置信度 字段索引从 `0` 开始时： ```text X=0, Y=1, Z=2, intensity=3, instance_id=4, semantic_label=5, instance_score=6 ``` 提交文件必须满足： 1. 每个测试 `.txt` 文件都必须有对应预测文件； 2. 预测文件的相对路径和文件名必须与测试集一致； 3. 每个预测文件的点数必须与对应测试文件完全一致； 4. 点顺序必须与测试文件完全一致； 5. `X Y Z intensity` 四列应保持与测试文件一致； 6. `semantic_label` 必须为整数，取值范围为 `0` 到 `8`； 7. `instance_id` 必须为非负整数； 8. `instance_score` 必须是 `[0,1]` 范围内的有限数值，不允许使用 `NaN` 或正负无穷。 9. 对于语义类别 `1` 到 `8` 的前景构件，不同实例应使用不同的实例编号； 10. 对于类别 `0` 的背景或未分类点，`instance_id` 可设为 `0`； 11. ZIP 根目录必须包含 `predictions/` 文件夹，不要额外嵌套一层目录。 ## **Citation** 使用 City-Facade 数据集开展研究或发表成果时，请引用： ```bibtex @article{chen2026cityfacade, title={City-Facade: A city-level large-scale point cloud building facade dataset for semantic \& instance segmentation}, author={Chen, Yiping and Li, Jonathan and Han, Ting and Feng, Huifang and Chen, Jun and Wang, Cheng}, journal={ISPRS Journal of Photogrammetry and Remote Sensing}, volume={232}, pages={675--688}, year={2026}, doi={10.1016/j.isprsjprs.2026.01.003} } ```
