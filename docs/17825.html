竞赛描述

在 Vaani 语料库的真实印度语言语音录音中检测噪声事件（开始和结束时间戳）。参赛者必须利用多层注释的训练数据（黄金级/白银级/青铜级）来构建稳健的噪声事件检测系统，该系统将基于事件级 F1 和分段 Dice 进行评估。

Overview

# Datathon@IndoML 2026 — 赛道1：噪声事件检测 ## 关于本赛事 **Datathon@IndoML 2026** 是与 [IndoML 2026](https://indoml.in) 联合举办的一项研究导向型数据科学竞赛。今年的数据马拉松挑战参赛者解决**印度语言真实语音中的噪声事件检测和消除** —— 这是实现跨印度语言包容性、稳健自动语音识别的关键问题。 ## 赛道1 — 检测 在印度语言语音录音中检测噪声事件，精确标注起始/终止时间戳。有效利用在不同级别（金级/银级/铜级）标注的数据来构建稳健的噪声事件检测系统。 保留的测试集（11小时）包含7小时的自然（真实）录音和4小时的合成录音（清晰语音加合成噪声）。赛道1基于全部11小时进行评分；自然/合成分解仅供透明性报告。训练数据（金级/银级/铜级共约150小时）可从Hugging Face获取：[ARTPARK-IISc/Vaani-Noise-Event-Dataset](https://huggingface.co/datasets/ARTPARK-IISc/Vaani-Noise-Event-Dataset)（下载代码包含其中；此赛道无需图像文件）。 在真实印度环境中收集的语音录音主要包含非平稳背景事件 —— 汽车喇叭声、狗叫声、儿童哭声、门铃声、手机铃声、厨房电器声和宗教音乐。这些事件会降低下游自动语音识别性能。 ## 动机 大多数学术语音增强基准围绕平稳噪声（白噪声、粉红噪声、咖啡厅嗡鸣声）或录音棚录制的混合音频构建。来自印度农村和半城市地区的现场录音包含突发性、语义丰富的事件 —— 经过的摩托车、母鸡、高压锅哨声、门铃、另一间房间的电视 —— 当前的去噪器要么会模糊处理，要么将其视为语音。 由此产生两个后果： - 下游自动语音识别在这些环境中的使用者身上表现失效，加剧了高资源语言和低资源印度语言之间现有的性能差距。 - 标准音频事件检测数据集（AudioSet、DESED、DCASE）代表性不足，既缺少印度声学背景，也缺少印度语言语音，使得从其迁移学习脆弱不堪。 本挑赛直接针对这一差距。它要求参赛者将噪声视为第一级、带标签、时间局部化的对象。 ## 负责任AI对齐 本挑赛在负责任AI赛道下定位，基于三个明确轴线： - **稳健性** —— 真实印度语言录音（非精心策划的录音棚混合音频）是评估分布。 - **包容性** —— Vaani涵盖多种印度语言和多种说话者。评估集按语言和类别平衡进行监控。 - **透明性** —— 前5名提交者必须公开代码并记录预训练依赖项。 ## 关键日期 | 事件 | 日期 | |------|------| | 竞赛开放 | 2026年8月1日 | | 提交截止 | 2026年9月15日 | | 结果宣布 | 待定 | | IndoML 2026演讲 | 待定 | ## 奖项 - **现金奖励** —— 表现最佳团队的丰厚现金奖励（详情待定）。 - **在IndoML 2026演讲** —— 邀请顶级团队向领先研究人员展示其解决方案。 - **创新奖** —— 专家评审团授予最具原创性方法论贡献的奖项。 ## 组织者 - Dr. Subhajit Datta —— 遗产技术研究所 - Dr. Mahesh Mohan —— 印度理工学院哈拉格普尔

Evaluation

<h1>评估 — 赛道 1：噪音事件检测</h1> <h2>提交格式</h2> <p> 提交一个包含单个文件 <code>predictions.jsonl</code> 的 <strong>ZIP 文件</strong>。 </p> <p> JSONL 文件的每一行必须是具有以下结构的 JSON 对象： </p> <pre> {"clip_id": "vaani_eval_001", "events": [{"onset": 1.24, "offset": 3.81}, {"onset": 5.10, "offset": 6.55}]} {"clip_id": "vaani_eval_002", "events": []} {"clip_id": "vaani_eval_003", "events": [{"onset": 0.20, "offset": 0.85}, {"onset": 3.44, "offset": 4.11}]} </pre> <ul> <li><strong>clip_id</strong>（字符串）— 必须与评估集中的片段 ID 匹配。</li> <li><strong>events</strong>（列表）— 检测到的噪音事件，每个包含： <ul> <li><strong>onset</strong>（浮点数）— 开始时间（秒）。</li> <li><strong>offset</strong>（浮点数）— 结束时间（秒）。</li> </ul> </li> <li>对于没有检测到噪音事件的片段，使用空列表 <code>[]</code>。</li> <li>每行一个 JSON 对象。每个评估片段必须恰好出现一次 — 这包括隐藏测试集中的<strong>自然和合成</strong>片段（总共 11 小时：7 小时自然 + 4 小时合成）。</li> </ul> <h2>评分范围</h2> <p> 赛道 1（检测）在<strong>完整测试集</strong>上评分 — 自然和合成片段合并。还会报告事件 F1 和分段 Dice 系数的自然/合成分组结果以供参考，但不影响排行榜排名。 </p> <h2>评估指标</h2> <h3>1. 基于事件的 F1（±20% 容差）</h3> <p> 当预测事件的开始时间和结束时间都在参考事件持续时间的 ±20% 范围内（最小 50 ms 容差）时，该预测事件被视为<strong>真正例</strong>。 </p> <p> 形式上，对于持续时间为 <em>d = offset − onset</em> 的参考事件： </p> <ul> <li>容差：<em>tol = max(0.20 × d, 0.05)</em> 秒</li> <li>匹配条件：|pred_onset − ref_onset| ≤ tol <strong>且</strong> |pred_offset − ref_offset| ≤ tol</li> </ul> <p> 事件按贪心匹配（最接近的优先）。计算微观平均 F1： </p> <pre> 精准率 = TP / (TP + FP) 召回率 = TP / (TP + FN) F1 = 2 × 精准率 × 召回率 / (精准率 + 召回率) </pre> <h3>2. 分段级 Dice 系数</h3> <p> 音频时间轴被分为 10 ms 的帧。对于每个片段，为参考和预测事件创建二进制帧级掩码。Dice 系数衡量时间重叠： </p> <pre> Dice = 2 × |P ∩ G| / (|P| + |G|) </pre> <p> 其中 P = 预测的噪音帧，G = 地面真实噪音帧。 在所有评估片段上进行宏观平均。 </p> <h3>综合得分（排行榜排名）</h3> <p> 用于排行榜排名的<strong>综合得分</strong>为： </p> <pre> 综合 = 事件 F1 + 分段 Dice </pre> <p> 最高可能值：2.0（完美 F1 = 1.0 + 完美 Dice = 1.0）。 </p> <h2>创新性得分</h2> <p> 在基于指标排名后，专家评审团对<strong>前 5 个参赛作品</strong>应用<strong>创新性因子</strong>以确定最终排名。这奖励原创贡献：新的架构、新颖的训练方案、原理性的事件条件设置或利用未标注 Vaani 音频的半监督方法。 </p> <h2>提交限制</h2> <table border="1" cellpadding="6"> <tr><td>每天最大提交次数</td><td>5</td></tr> <tr><td>最大总提交次数</td><td>100</td></tr> <tr><td>执行时间限制</td><td>600 秒</td></tr> </table>
