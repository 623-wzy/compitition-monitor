Overview

# LiDAR视觉惯性SLAM 这是多传感器LiDAR SLAM挑战赛2026的独立LiDAR视觉惯感融合赛道。参赛者本地处理两个发布场景并仅提交估计轨迹。可靠的地面真值及其时间戳在Codabench上保持私密。 两个场景`scene_0001`和`scene_0002`为必需。完成没有硬性阈值；轨迹覆盖不足会降低AUC召回率和最终分数。 该数据集由Airy LiDAR及其内置IMU加上前左和前右Seeker鱼眼相机采集。以下图像仅为路线形状参考，不包含地面真值。 ![场景1轨迹参考](images/scene_0001_trajectory_reference.png) ![场景2轨迹参考](images/scene_0002_trajectory_reference.png)

Submission

# 提交格式 上传一个ZIP文件，其根目录包含 `README.md` 和 `trajectories/scene_0001.txt` 以及 `trajectories/scene_0002.txt`。每个轨迹使用TUM格式： ```text timestamp tx ty tz qx qy qz qw ``` 时间戳必须严格递增。数值必须是有限的，四元数必须非零。提交次数无限制。仅最新的有效提交将参与排名。

Evaluation

# 评估方法 评分使用EVO时间同步和每个场景一个无缩放SE(3)对齐与私密参考轨迹进行对比。完成度没有硬阈值且公开发布；缺失的位姿对会降低AUC召回率。评估时间戳和真值不公开。 ATE是EVO平移APE RMSE。AUC使用EVO单帧平移RPE和F1-AUC协议。RTE是EVO平移RPE的RMSE，在1m、5m和10m处进行归一化。总体和单场景RTE@1m、RTE@5m和RTE@10m均与合并RTE一起公开。超过0.3s的间隙永远不会跨越。 AUC和RTE使用对齐的世界坐标系位置（姿态为恒等）计算，因此固定的参与者机体坐标系约定不会影响平移分数。每个场景使用一个场景级SE(3)对齐。 总分数为`100 * (0.40 * AUC + 0.40 * exp(-ATE / tau_ate) + 0.20 * exp(-RTE / tau_rte))`。参考结果为发布的参考：其总体ATE和RTE在最终评分器冻结后定义`tau_ate`和`tau_rte`。 结果公开总分、总体和单场景的AUC/ATE/合并RTE/RTE@1m/RTE@5m/RTE@10m、归一化分数分量、完成度和匹配计数。每个时间戳的误差、关联、对齐变换和真值保持私密。
