background:#fff8e6; padding:10px 14px; margin:0 0 18px;"> <strong>更新 —</strong> <strong>意向书截止日期延长至2026年8月15日</strong>（原定7月25日）。所有其他日期保持不变。 </p> <p><em>2026年IEEE大数据杯的一个赛道，与<a href="https://bigdataieee.org/BigData2026/">IEEE国际大数据会议（IEEE BigData）2026年、美国亚利桑那州凤凰城</a>联合举办。</em></p> <p> 路侧激光雷达感知在智能交通系统中的发展受到大规模、标注完善的真实数据集的成本和稀缺性的限制。本挑战提出的问题是：合成激光雷达数据是否足够真实，使得在其上训练的深度学习模型能够泛化到真实激光雷达帧？ </p> <p> 为此，本挑战要求参赛者生成针对<strong>LUMPI</strong>分布的合成激光雷达数据，基于该数据训练目标检测器，并在真实的保留测试帧上提交检测结果。评分基于：（1）其合成帧与真实帧的分布接近程度，以及（2）仅在合成数据上训练的检测器在真实帧上的性能。 </p> <h2>重要日期</h2> <ul> <li><strong>意向书截止日期：</strong> <strong>2026年8月15日</strong>（从7月25日延长）</li> <li><strong>最终报告和解决方案提交截止日期：</strong> 2026年11月15日</li> <li><strong>获胜团队公布：</strong> 2026年11月25日</li> <li><strong>会议：</strong> 2026年12月14-17日</li> </ul> <h2>参赛者参考资源</h2> <p> 为支持寻求文档化起点的参赛者，我们公开提供完整的参考管道，涵盖合成方法论、经验分析、现成可用的合成数据集，以及开源激光雷达数据处理和可视化软件。这些材料作为参考方向提供，不是必需要求。 </p> <p> 合成管道在<a href="https://arxiv.org/pdf/2509.02903">UrbanTwin：为Sim2Real激光雷达感知和评估构建高保真数字孪生体（arXiv预印本）</a>中描述，更深入的经验分析（包括本挑战采用的分布现实性指标）在<a href="https://scholar.google.com/scholar?oi=bibs&cluster=6844982498826808010&btnI=1&hl=en">为弥合基于激光雷达的ITS感知中Sim2Real差距的高保真数字孪生体（IEEE T-ITS，2026）</a>中介绍。 </p> <p> 使用该管道生成的合成激光雷达数据集在<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">UrbanTwin：合成路侧激光雷达数据集（IEEE OJ-ITS，2026）</a>中发布，可从<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">Harvard Dataverse</a>下载。每个数据集包含<strong>10K帧</strong>，跨越<strong>六个目标类别</strong>标注，用于<strong>检测、跟踪和分割任务</strong>，并直接兼容此处使用的多类评估；论文中的经验分析包括分布现实性指标和单类三维目标检测研究作为概念验证。为实现端到端激光雷达处理，我们还提供<a href="https://ieeexplore.ieee.org/document/11498694">LiGuard框架（IEEE T-IV，2026）</a>及相关内容。 </p>

Evaluation

<h1>评估协议</h1> <p> 计算两个分数并将其合并为单一的<em>综合</em>分数，该分数确定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合：</p> <ol> <li>将50个提交的合成帧连接成一个集合<code>S_syn</code>；将50个保留的真实参考帧连接成<code>S_real</code>。</li> <li>将两者都掩蔽到点云范围<code>[-40, -40, -5, 40, 40, 5]</code>。</li> <li>以种子1234均匀随机下采样至每侧<strong>N = 10,000个点</strong>（与启动工具包中的本地评估器使用的种子相同）。</li> <li>在整个10,000点集合中计算<strong>一个</strong> CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离（CD）</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻成本；对称。越低越好。</p> <h3>1b. 最大均值差异（MMD）</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计（非对角线）。带宽<code>γ</code>由1,000点联合子样本的中位数启发式设置（<code>γ = 1 / (2 · median ||x - y||²)</code>），以便内核在激光雷达空间尺度下不会饱和。越低越好。 </p> <h3>1c. 地球搬运距离（EMD）</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> 欧几里得地面成本的Wasserstein-1，由网络单纯形精确求解（POT的<code>ot.emd2</code>）。以米为单位报告。越低越好。 </p> <h3>1d. 弗雷歇点云距离（FPD）</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> FID风格：为每个集合的点拟合一个3元高斯分布，计算高斯分布之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 3D物体检测</h2> <p> 参与者在50个真实激光雷达帧上提交检测（<code>predictions.json</code>），这些帧的真实值被保留。我们在<strong>本赛道定义的8个物体类别</strong>（<em>行人、汽车、自行车、摩托车、公交车、卡车、货车、未知</em>）上计算平均精度，IoU阈值为0.5（主要）和0.7（次要）。报告按类AP，<strong>类间平均AP（mAP）</strong>为排行榜检测分数；保留集中真实实例为零的类被排除在均值外。报告KITTI 11点和40点插值AP；40点形式为排行榜主要形式。 </p> <p> 真实值和预测框使用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个有向BEV矩形的3D交并比乘以Z重叠。KITTI截断/遮挡/最小高度难度过滤器不适用，因为这些依赖于对路边激光雷达数据集不自然的2D边界框标注。 </p> <p>本赛道的有效类字符串列在<code>config.json</code>（在<code>reference_data/</code>中提供）和启动工具包中的<code>submission_format.md</code>中。任何具有无法识别的类标签的预测都被丢弃。</p> <h2>3. 综合分数</h2> <p>每个分量使用每个赛道的标准化范围被最小-最大标准化到[0, 1]：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 → 1 - clip) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 → clip) score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 标准化端点在<code>config.json</code>（在<code>reference_data/</code>中提供）中公开，因此本地评估器和服务器评估结果一致。 </p>

Data

# 数据 ## LUMPI 实际**LUMPI**数据可从其原始发布来源公开获取。我们不重新分发这些数据。参与者必须根据其许可证直接从来源获得真实数据集。 - **来源：** https://data.uni-hannover.de/dataset/lumpi - **许可证：** 见上述来源。 ## 为参与者发布的内容 起始工具包（*Files*标签 → starting_kit）包含： - `detection_test_frames/` — **50个真实激光雷达帧**（仅点云，无标签），您必须在这些帧上运行检测器并提交预测。 - `detection_test_frame_ids.json` — 您的`predictions.json`必须按顺序覆盖的规范帧ID列表。 - `forbidden_frames.txt` — **100个帧ID，您不得在其上进行训练、验证或超参数调整**。这是50个检测测试帧和50个真实性参考帧的并集。基于荣誉制，由提交时的签署声明强制执行。 - `local_eval.py` — 与Codabench工作程序相同的评分程序。在本地运行以复现服务器分数（精确到比特），给定从发布的检测测试帧生成的虚拟参考集。 - `make_dummy_submission.py` — 生成已知的无效提交来演示格式。对于检查您的流程很有用。 - `submission_format.md` — 完整提交规范。 ## 保留的内容（仅组织方） - 用作**真实性参考集**的50个真实帧。 - 50个检测测试帧的真值框。 ## 评估的类别 此赛道基于为**LUMPI**数据集定义的**8**个对象类别进行评分： *Person, Car, Bicycle, Motorcycle, Bus, Truck, Van, Unknown*。排行榜的检测分数是这些类别的平均AP；在保留的50帧集中没有真值实例的类被排除在平均值之外。 ## 数据划分 数据划分是使用固定种子1234进行的分层随机采样。确切的帧ID列表已在起始工具包中发布，任何人都可以从发布的真实数据集中复现这些分割。 ## 参考基线 下面的数字仅针对*Car*类别报告，取自该数据集上的先前工作。排行榜的检测分数是此赛道定义的所有类别的平均AP（见**评估**），因此提交的评分覆盖范围比这些单类参考更广。包含这些基线是为了演示sim → real迁移在此基准上是可行的，并为您迭代时提供单类参考点以便定向。 | 系统 | Car 3D AP @ 0.5 | Car 3D AP @ 0.7 | |------|-----------------|-----------------| | SEED（真实LUMPI训练，IEEE T-ITS 2026） | 0.4270 | n/r | | SEED（UT-LUMPI合成 → 真实LUMPI，IEEE T-ITS 2026） | 0.4474 | n/r |

Submission

# 提交格式 <p>将以下所有内容打包到单个 <code>submission.zip</code> 文件中，并在"提交"选项卡上上传。</p> <pre> submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好50个文件 ├── predictions.json └── declaration.pdf # 签署的诚信声明（PDF）。也接受 declaration.txt。 </pre> <h2>synthetic/&lt;id&gt;.bin</h2> <ul> <li>恰好 <strong>50</strong> 个文件。</li> <li>每个文件均为原始 <code>float32</code> 格式，形状为 <code>N × 3</code>，行主序存储，通道为 <code>(x, y, z)</code>（单位：米）。</li> <li>接受 <code>N × 3</code> 或 <code>N × 4</code>（xyz + 强度）格式；如果存在强度列，则在评分前将其删除。</li> <li>每个文件磁盘空间 ≤ 1.5 MB（约125,000个点）。真实度评估在数据集级别进行：将所有50帧连接，掩蔽到轨迹点云范围，然后子采样到10,000个点（种子1234）后计算 CD / MMD / EMD / FPD。提交更密集的帧不会改善分数；帧顺序无关。</li> <li>最简单的有效命名方式是 <code>0001.bin … 0050.bin</code>。</li> </ul> <h2>predictions.json</h2> <p>JSON对象，其键为来自 <code>detection_test_frame_ids.json</code>（在初始工具包中）的帧ID。对于每个帧ID，您必须包含一个条目，即使该值为空列表。</p> <pre> { "&lt;frame_id_1&gt;": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "Car"}, {"box": [...], "score": 0.81, "class": "Person"} ], "&lt;frame_id_2&gt;": [], ... } </pre> <ul> <li><code>box</code>：7个浮点数，遵循 OpenPCDet 约定。<code>(x, y, z)</code> 是LiDAR框架中的框 <em>中心</em>（单位：米），<code>(dx, dy, dz)</code> 是沿框局部轴的完整范围，<code>heading</code> 是绕 <code>+Z</code> 的旋转角度（单位：弧度）。</li> <li><code>score</code>：置信度范围 [0, 1]。</li> <li><code>class</code>：该轨迹的有效类别字符串之一。有效值：<code>Person</code>、<code>Car</code>、<code>Bicycle</code>、<code>Motorcycle</code>、<code>Bus</code>、<code>Truck</code>、<code>Van</code>、<code>Unknown</code>。类别字符串匹配不区分大小写。计算AP前，具有无法识别类别字符串的预测将被丢弃。</li> </ul> <h2>declaration.pdf（或 declaration.txt）</h2> <p>初始工具包中提供 <code>declaration_template.pdf</code>，这是一份单页表格，预印了必需的诚信声明和签名行。填写团队名称和日期，签名（使用任何PDF工具进行数字签名，或打印 → 签名 → 扫描），另存为 <code>declaration.pdf</code>，并将其包含在每次提交中。</p> <p>如果您无法轻松生成签署的PDF，也接受纯文本 <code>declaration.txt</code>。必需声明（逐字，不区分大小写）：</p> <blockquote> <em>我确认我没有针对 <code>forbidden_frames.txt</code> 中列出的任何帧进行训练，并且所有提交的检测都由仅在我生成的合成数据上训练的模型产生。</em> </blockquote> <h2>返回结果</h2> <p>评分后（对于有效提交通常少于5分钟），您将在排行榜上看到您的位置，以及包含所有组件指标的 <em>详细结果</em> 视图，包括按类别的AP。</p>

Rules

<h1>规则</h1> <h2>资格条件</h2> <ul> <li>对所有人开放——研究人员、学生、行业团队。</li> <li>每支团队必须注册一个参与者账户；不得维护多个账户。</li> </ul> <h2>允许的内容</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理引擎）。开源或闭源——重要的是合成数据。</li> <li>任何3D目标检测器架构，仅在<em>你的合成数据</em>上训练。</li> <li>检测器训练期间应用的增强方法（旋转、缩放、翻转、真值采样、噪声）——它们作用于合成数据，而不是禁止的真实帧。</li> <li>使用公共真实数据集的<strong>训练集分割</strong>进行超参数选择或域适配，<em>前提是不触及任何禁止帧</em>。（禁止列表仅包含100个保留帧，不包含整个真实训练集分割。）</li> </ul> <h2>禁止的内容</h2> <ul> <li>从<code>forbidden_frames.txt</code>中列出的100个帧中的<em>任何</em>帧进行训练、验证、超参数调整或以其他方式观察真值。这由签名声明强制执行，是该挑战的基础完整性规则。</li> <li>提交由在<em>任何</em>路侧激光雷达数据集的真实标签上训练的模型产生的预测。检测器必须仅基于仿真训练。</li> <li>通过Codabench排行榜信号反向工程或推断保留的真实性参考帧（例如，探测设计用于泄露参考集身份的提交）。发现进行此操作的提交将被取消资格。</li> <li>多个账户、子团队账户或跨注册团队的协调。</li> </ul> <h2>取消资格</h2> <p> 组织者保留权利对任何提交的合成帧和预测进行检查，以查证是否存在禁止帧泄露证据（例如，与保留真实帧可疑相似的合成帧；其分布意味着访问了保留真值的预测）。被取消资格的参与者将从排行榜和奖项考虑中删除。 </p> <h2>奖项</h2> <p>每个赛道：第一名USD 500、第二名USD 300、第三名USD 200。赞助商将在开发阶段开始前宣布。</p> <h2>发表和署名</h2> <ul> <li>每支参赛队伍提交一份<strong>4-8页的挑战报告</strong>，描述其方法，截止日期为最终阶段截止日期（2026年11月15日）。</li> <li>倾向于不发表的团队可选择加入其提交的<em>非发表赛道</em>。</li> <li>每个赛道的前3名团队受邀在亚利桑那州凤凰城的IEEE BigData 2026大数据杯研讨会会议上进行报告（2026年12月14-17日），并通过挑战的相关论文赛道向IEEE BigData 2026会议论文集提交完整论文。</li> <li>挑战组织者可发布所有提交的汇总分析（匿名，除非获得明确许可）。</li> </ul>
