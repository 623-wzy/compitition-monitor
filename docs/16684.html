<h1>评估协议</h1> <p> 计算两个分数并合并为一个<em>综合</em>分数，该分数决定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合：</p> <ol> <li>将50个提交的合成帧拼接为一个集合<code>S_syn</code>；将50个留出的真实参考帧拼接为<code>S_real</code>。</li> <li>将两者裁剪至点云范围<code>[-40, -40, -5, 40, 40, 5]</code>。</li> <li>使用随机种子1234（与入门套件中本地评估器使用的种子相同），在每侧均匀随机子采样至<strong>N = 10,000个点</strong>。</li> <li>在整个10,000点集合上计算<strong>一个</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. Chamfer距离（CD）</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻代价；对称。越低越好。</p> <h3>1b. 最大均值差异（MMD）</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计量（非对角线）。带宽<code>γ</code>通过1,000点联合子样本的中位数启发式方法设置（<code>γ = 1 / (2 · 中位数 ||x - y||²)</code>），以使核函数在激光雷达空间尺度上不会饱和。越低越好。 </p> <h3>1c. 推土机距离（EMD）</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> 使用欧几里得地面成本的Wasserstein-1距离，通过网络单纯形法（POT的<code>ot.emd2</code>）精确求解。以米为单位报告。越低越好。 </p> <h3>1d. Data

<h1>数据</h1> <h2>LUMPI</h2> <p> 真实<strong>LUMPI</strong>数据自其最初发布以来即可公开获取。我们不再重新分发。参与者必须在其自有许可下直接从数据源获取真实数据集。 </p> <ul> <li><strong>来源：</strong> <a href="https://data.uni-hannover.de/dataset/lumpi">https://data.uni-hannover.de/dataset/lumpi</a></li> <li><strong>许可协议：</strong> 见数据源。</li> </ul> <h2>向参与者发布的内容</h2> <p>起步套件（<em>Files</em>标签页 → starting_kit）包含：</p> <ul> <li><code>detection_test_frames/</code> —— <strong>50帧真实激光雷达数据</strong>（仅点云，无标注），您必须在其上运行检测器并提交预测结果。</li> <li><code>detection_test_frame_ids.json</code> —— 您的<code>predictions.json</code>必须按顺序覆盖的帧ID规范列表。</li> <li><code>forbidden_frames.txt</code> —— <strong>100个禁止用于训练、验证或超参数调优的帧ID</strong>。这是50个检测测试帧与50个真实度参考帧的并集。基于诚信制度，通过您提交时的签字声明强制执行。</li> <li><code>local_eval.py</code> —— 发送至Codabench工作节点的精确评分程序。在本地运行它以逐位复现服务器评分，前提是您从发布的检测测试帧生成一个虚拟参考集。</li> <li><code>make_dummy_submission.py</code> —— 生成一个已知错误的提交，用于测试格式。有助于对您的流程进行合理性检查。</li> <li><code>submission_format.md</code> —— 完整的提交规范。</li> </ul> <h2>保留数据（仅组织者可访问）</h2> <ul> <li>50帧用作<em>真实度参考集</em>的真实数据。</li> <li>50个检测测试帧的真值框。</li> </ul> <h2>评估类别</h2> <p> 本赛道对<strong>LUMPI</strong>数据集定义的<strong>8</strong>个目标类别进行评分：<em>行人、轿车、自行车、摩托车、公交车、卡车、面包车、未知</em>。排行榜的检测分数为这些类别的平均精度（AP）均值；在保留的50帧数据集中真值实例为零的类别不参与均值计算。 </p> <h2>数据划分</h2> <p> 数据划分为使用固定随机种子1234的分层随机抽样。确切的帧ID列表公布在起步套件中，以便任何人都能从发布的真实数据集中复现这些划分。 </p> <h2>参考基线</h2> <p> 以下数值仅针对<em>轿车</em>类别报告，取自该数据集的前期工作。排行榜的检测分数为本赛道定义的所有类别的平均精度（AP）均值（见<strong>评估</strong>部分），因此提交作品的评分范围比这些单类别参考更广。纳入这些基线是为了证明在该基准上仿真到真实的迁移是可行的，并为您在迭代过程中提供逐类别的参考方向。 </p> <table border="1" cellpadding="6"> <tr> <th>系统</th><th>轿车 3D AP @ 0.5</th><th>轿车 3D AP @ 0.7</th> </tr> <tr> <td>SEED（真实LUMPI训练，IEEE T-ITS 2026）</td> <td>0.4270</td> <td>无报告</td> </tr> <tr> <td>SEED（UT-LUMPI合成数据→真实LUMPI，IEEE T-ITS 2026）</td> <td>0.4474</td> <td>无报告</td> </tr> </table>

Submission

<h1>提交格式</h1> <p>将以下内容全部打包到一个 <code>submission.zip</code> 文件中，并在<em>提交</em>标签页上传。</p> <pre> submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好50个文件 ├── predictions.json └── declaration.pdf # 签署的诚信声明（PDF）。也接受 declaration.txt。 </pre> <h2>synthetic/&lt;id&gt;.bin</h2> <ul> <li>恰好 <strong>50</strong> 个文件。</li> <li>每个文件为原始 <code>float32</code> 格式，形状为 <code>N × 3</code>，行优先顺序，通道为 <code>(x, y, z)</code>，单位为米。</li> <li>接受 <code>N × 3</code> 或 <code>N × 4</code>（xyz + 强度）格式；如果存在强度列，在评分前会被丢弃。</li> <li>每个文件磁盘大小 ≤ 1.5 MB（约125,000个点）。真实度在数据集层面计算：所有50帧被拼接，掩码处理至赛道点云范围，然后子采样至10,000个点（随机种子1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会提高分数；帧的顺序无关紧要。</li> <li>最简单的有效命名方式为 <code>0001.bin … 0050.bin</code>。</li> </ul> <h2>predictions.json</h2> <p>JSON对象，其键为来自 <code>detection_test_frame_ids.json</code>（在起始工具包中）的帧ID。对于每个帧ID，必须包含一个条目，即使值为空列表。</p> <pre> { "&lt;frame_id_1&gt;": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "Car"}, {"box": [...], "score": 0.81, "class": "Person"} ], "&lt;frame_id_2&gt;": [], ... } </pre> <ul> <li><code>box</code>：7个浮点数，OpenPCDet约定。<code>(x, y, z)</code> 为边界框<em>中心</em>在LiDAR坐标系中的位置（单位：米），<code>(dx, dy, dz)</code> 为沿边界框局部轴的完整尺寸，<code>heading</code> 为绕 <code>+Z</code> 轴的旋转角度（弧度）。</li> <li><code>score</code>：[0, 1] 区间内的置信度。</li> <li><code>class</code>：此赛道有效的类别字符串之一。 有效值：<code>Person</code>、<code>Car</code>、<code>Bicycle</code>、 <code>Motorcycle</code>、<code>Bus</code>、<code>Truck</code>、 <code>Van</code>、<code>Unknown</code>。类别字符串不区分大小写匹配。包含无法识别类别字符串的预测将在计算AP前被丢弃。</li> </ul> <h2>declaration.pdf（或 declaration.txt）</h2> <p>起始工具包中包含 <code>declaration_template.pdf</code>，这是一页预印了所需诚信声明和签名行的表格。填写团队名称和日期，签名（可使用任何PDF工具电子签名，或打印 → 签名 → 扫描），保存为 <code>declaration.pdf</code>，并包含在每次提交中。</p> <p>如果您无法轻松生成签署的PDF，也接受纯文本 <code>declaration.txt</code>。所需声明（原文照录，不区分大小写）：</p> <blockquote> <em>I confirm that I did not train on any frame listed in <code>forbidden_frames.txt</code>, and that all submitted detections were produced by a model trained only on synthetic data I generated.</em> </blockquote> <h2>返回内容</h2> <p>评分后（有效提交通常少于5分钟），您将看到自己在排行榜上的位置，以及包含所有分项指标（包括每类AP）的<em>详细结果</em>视图。</p>

Rules

<h1>规则</h1> <h2>参赛资格</h2> <ul> <li>面向所有人员开放 — 研究人员、学生、行业团队。</li> <li>每支团队必须注册一个参赛账号；请勿维护多个账号。</li> </ul> <h2>允许事项</h2> <ul> <li>任何模拟框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、生成对抗网络、自定义物理引擎）。开源或闭源均可 — 关键在于合成数据。</li> <li>任何3D目标检测器架构，但必须仅在<em>您的合成数据</em>上进行训练。</li> <li>检测器训练期间应用的数据增强（旋转、缩放、翻转、真值采样、噪声）— 这些操作针对合成数据，而非禁止使用的真实帧。</li> <li>使用公开真实数据集的<strong>训练集</strong>进行超参数选择或域适应，<em>前提是未接触任何禁止帧</em>。（禁止列表仅包含100个保留帧，而非整个真实训练集。）</li> </ul> <h2>禁止事项</h2> <ul> <li>对<code>forbidden_frames.txt</code>中列出的100个帧中的<strong>任何</strong>一帧进行训练、验证、超参数调优，或以其他方式观察其真值。这通过签署声明强制执行，是本挑战赛的基础诚信规则。</li> <li>提交由曾在<em>任何</em>路边激光雷达数据集的真实标签上训练过的模型生成的预测结果。检测器必须仅使用模拟数据。</li> <li>通过Codabench排行榜信号逆向工程或推断被保留的真实参考帧（例如，设计用于泄露参考集身份的探测性提交）。发现此类行为的提交将被取消资格。</li> <li>拥有多个账号、子团队账号，或在已注册团队之间进行协调。</li> </ul> <h2>取消资格</h2> <p> 组织者保留检查任何提交作品的合成帧和预测结果的权利，以查找禁止帧泄露的证据（例如，与保留真实帧高度相似的合成帧；其分布暗示接触过保留真值的预测结果）。被取消资格的参与者将从排行榜和奖项评选中移除。 </p> <h2>奖项</h2> <p>每条赛道：第一名500美元，第二名300美元，第三名200美元。赞助方将在开发阶段开始前公布。</p> <h2>发表与署名</h2> <ul> <li>每个参赛团队需提交一份<strong>4–8页的竞赛报告</strong>，描述其方法，截止日期为最终阶段截止日期（2026年11月15日）。</li> <li>不愿发表的团队可以选择将其提交纳入<em>不发表赛道</em>。</li> <li>每条赛道的前三名团队将获邀在IEEE BigData 2026大数据杯研讨会（2026年12月14日至17日，亚利桑那州凤凰城）上进行展示，并可通过挑战赛关联的论文通道向IEEE BigData 2026会议论文集提交完整论文。</li> <li>挑战赛组织者可能会发表对所有提交作品的汇总分析（匿名处理，除非获得明确许可）。</li> </ul>
