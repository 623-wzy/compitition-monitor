background:#fff8e6; padding:10px 14px; margin:0 0 18px;"> <strong>更新 —</strong> <strong>意向书截止日期延长至2026年8月15日</strong> （之前为7月25日）。其他日期保持不变。 </p> <p><em>2026年IEEE大数据杯的一个赛道，与<a href="https://bigdataieee.org/BigData2026/">IEEE国际大数据会议（IEEE BigData）2026、美国亚利桑那州凤凰城</a>联合举办。</em></p> <p> 智能运输系统中路侧激光雷达感知的瓶颈在于大规模、标注精良的真实数据集的成本高且稀缺。本挑战赛提出的问题是：是否可以使合成激光雷达数据足够逼真，使得在其上训练的深度学习模型能够泛化到真实激光雷达帧？ </p> <p> 为此，本挑战赛要求参赛者生成针对<strong>V2X-Real</strong>分布的合成激光雷达数据，在该数据上训练目标检测器，并在真实的保留帧上提交检测结果。评分基于以下两项：（1）其合成帧与真实帧的分布接近度，以及（2）仅基于模拟数据的检测器在真实帧上的性能。 </p> <h2>重要日期</h2> <ul> <li><strong>意向书截止日期：</strong><strong>2026年8月15日</strong>（从7月25日延长）</li> <li><strong>最终报告和方案提交截止日期：</strong>2026年11月15日</li> <li><strong>获奖团队公布日期：</strong>2026年11月25日</li> <li><strong>会议时间：</strong>2026年12月14-17日</li> </ul> <h2>参赛者参考资源</h2> <p> 为了为希望获得有文献记载的起点的参赛者提供支持，我们公开提供完整的参考管道，涵盖合成方法、实证分析、即用型合成数据集以及开源激光雷达数据处理和可视化软件。这些材料作为指导提供，而非要求。 </p> <p> 合成管道在<a href="https://arxiv.org/pdf/2509.02903">UrbanTwin：为Sim2Real激光雷达感知和评估构建高保真数字孪生（arXiv预印本）</a>中有所介绍，更深入的实证分析（包括本挑战赛采用的分布真实性指标）见<a href="https://scholar.google.com/scholar?oi=bibs&amp;cluster=6844982498826808010&amp;btnI=1&amp;hl=en">高保真数字孪生用于弥合激光雷达ITS感知中的Sim2Real差距（IEEE T-ITS，2026）</a>。 </p> <p> 用该管道生成的合成激光雷达数据集发布在<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">UrbanTwin：合成路侧激光雷达数据集（IEEE OJ-ITS，2026）</a>中，可在<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">哈佛数据源</a>下载。每个数据集包含<strong>10000帧</strong>数据，跨越<strong>六个目标类别</strong>，用于<strong>检测、跟踪和分割任务</strong>，与此处使用的多类评估直接兼容；论文中的实证分析包括分布真实性指标和单类3D目标检测研究作为概念验证。为实现端到端激光雷达处理，我们还提供<a href="https://ieeexplore.ieee.org/document/11498694">LiGuard框架（IEEE T-IV，2026）</a>

Evaluation

<h1>评估协议</h1> <p> 计算两个分数并将其合并为单一的<em>综合</em>分数，该分数决定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合步骤：</p> <ol> <li>将50个提交的合成帧连接成一个集合<code>S_syn</code>；将50个保留的真实参考帧连接成<code>S_real</code>。</li> <li>将两者都掩蔽到点云范围<code>[-40, -40, -8, 40, 40, 2]</code>。</li> <li>使用种子1234均匀随机下采样到每侧<strong>N = 10,000个点</strong>（与启动工具包中的本地评估器使用的种子相同）。</li> <li>在整个10,000点集合上计算<strong>一次</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离(CD)</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻代价；对称。越低越好。</p> <h3>1b. 最大均值差异(MMD)</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计量（非对角线）。带宽<code>γ</code>通过1,000点联合子样本上的中位数启发式设置（<code>γ = 1 / (2 · median ||x - y||²)</code>），使核在激光雷达空间尺度上不会饱和。越低越好。 </p> <h3>1c. 地球移动者距离(EMD)</h3> <pre> EMD(X, Y) = √( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> Wasserstein-1距离，采用欧几里得基础代价，由网络单纯形法精确求解（POT的<code>ot.emd2</code>）。以米为单位报告。越低越好。 </p> <h3>1d. 弗雷歇点云距离(FPD)</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> FID风格：对每个集合的点拟合3变量高斯分布，计算高斯分布之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 3D目标检测</h2> <p> 参与者在50个真实激光雷达帧上提交检测结果（<code>predictions.json</code>），这些帧的真实值被隐藏。我们在本赛道定义的<strong>3个目标类别</strong>（<em>车辆、行人、卡车</em>）上计算平均精度，在IoU阈值0.5（主要）和0.7（次要）处。报告按类AP，并且<strong>跨类平均AP（mAP）</strong>是排行榜的检测分数；在保留集中零个真实实例的类被排除在平均值外。报告KITTI 11点和40点插值AP；40点形式是排行榜的主要形式。 </p> <p> 真实值和预测框使用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个有向BEV矩形的3D交并比乘以Z重叠。未应用KITTI截断/遮挡/最小高度难度过滤器，因为这些取决于2D边界框注释，这对于路边激光雷达数据集不自然。 </p> <p>本赛道的有效类字符串列在<code>config.json</code>中（包含在<code>reference_data/</code>中）和启动工具包中的<code>submission_format.md</code>中。任何带有无法识别的类标签的预测都将被丢弃。</p> <h2>3. 综合分数</h2> <p>每个分量使用按赛道的归一化范围最小-最大归一化到[0, 1]：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 → 1 - clip) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 → clip) score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 归一化端点在<code>config.json</code>中公开（包含在<code>reference_data/</code>中），因此本地评估器和服务器计算相同的分数。 </p>

Data

# 数据 ## V2X-Real 真实 **V2X-Real** 数据已从其原始版本公开发布。我们不重新分发它。参赛者必须根据其自身许可证直接从原始来源获取真实数据集。 - **来源：** https://github.com/ucla-mobility/V2X-Real - **许可证：** 见来源 ## 为参赛者发布的文件 起始工具包（*文件*选项卡 → starting_kit）包含： - `detection_test_frames/` — **50帧真实激光雷达点云**（仅点云，无标签），您必须在这些点云上运行检测器并提交预测结果。 - `detection_test_frame_ids.json` — 您的 `predictions.json` 必须涵盖的标准帧ID列表（按顺序）。 - `forbidden_frames.txt` — **100个禁止用于训练、验证或超参数调整的帧ID**。这是50个检测测试帧和50个真实性参考帧的并集。基于荣誉制，由您提交中的签署声明强制执行。 - `local_eval.py` — 发送到Codabench工作器的精确评分程序。在本地运行以重现服务器分数（位精确度），给定从发布的检测测试帧生成的虚拟参考集。 - `make_dummy_submission.py` — 生成已知的不良提交以验证格式。对于完整性检查您的流程很有用。 - `submission_format.md` — 完整的提交规范。 ## 保密（仅组织方） - 用作*真实性参考集*的50帧真实数据。 - 50个检测测试帧的真实标注框。 ## 评估类别 本赛道在**V2X-Real**数据集定义的**3个**物体类别上评分： *车辆、行人、卡车*。排行榜的检测分数是这些类别的平均AP；在保密的50帧集中没有真实标注实例的类别被排除在平均值之外。 ## 数据划分 数据划分是使用固定种子1234的分层随机样本。确切的帧ID列表已在起始工具包中发布，任何人都可以从发布的真实数据集中重现它们。 ## 参考基线 下面报告的数字来自该数据集的先前工作，仅针对*车*类别报告。排行榜的检测分数是本赛道定义的所有类别的平均AP（见**评估**），所以提交结果的评分覆盖范围比这些单类别参考更广。包含基线是为了展示sim→real迁移在此基准上是可实现的，并在您进行迭代时为单类别参考点提供方向。 | 系统 | 车 3D AP @ 0.5 | 车 3D AP @ 0.7 | |------|----------------|----------------| | V2X-Real 无融合基准（SECOND，真实） | 0.3556 | n/r | | SECOND（UT-V2X-Real合成 → V2X-Real-IC，IEEE T-ITS 2026） | 0.6318 | n/r |

Submission

# 提交格式 将以下所有内容打包到单个 `submission.zip` 文件中，并在*提交*选项卡上上传。 ``` submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好 50 个文件 ├── predictions.json └── declaration.pdf # 签署的荣誉声明 (PDF)。也接受 declaration.txt。 ``` ## synthetic/<id>.bin - 恰好 **50** 个文件。 - 每个文件是原始 `float32` 格式，形状 `N × 3`，行主序排列，通道为 `(x, y, z)` 单位为米。 - 接受 `N × 3` 或 `N × 4` (xyz + 强度)；若存在强度列，在评分前将被丢弃。 - 每个文件 ≤ 1.5 MB (~125,000 个点)。真实性在数据集级别计算：所有 50 帧连接，掩蔽到轨迹的点云范围，然后子采样到 10,000 个点 (种子 1234) 后计算 CD / MMD / EMD / FPD。提交更密集的帧不会改进分数；帧顺序无关紧要。 - 最简单的有效命名为 `0001.bin … 0050.bin`。 ## predictions.json JSON 对象，其键为来自 `detection_test_frame_ids.json` (在入门工具包中) 的帧 ID。必须为每个帧 ID 包含一个条目，即使该值为空列表。 ```json { "<frame_id_1>": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "vehicle"}, {"box": [...], "score": 0.81, "class": "pedestrian"} ], "<frame_id_2>": [], ... } ``` - `box`: 7 个浮点数，OpenPCDet 约定。`(x, y, z)` 是盒子*中心*在 LiDAR 坐标系中的位置 (单位为米)，`(dx, dy, dz)` 是沿盒子本地轴的完整范围，`heading` 是绕 `+Z` 的旋转 (单位为弧度)。 - `score`: 置信度，范围 [0, 1]。 - `class`: 此轨迹的有效类字符串之一。有效值：`vehicle`、`pedestrian`、`truck`。类字符串匹配不区分大小写。具有无法识别的类字符串的预测在计算 AP 前被丢弃。 ## declaration.pdf (或 declaration.txt) 入门工具包包含 `declaration_template.pdf`，一份单页表单，其中预先打印了必需的荣誉声明和签名行。填写团队名称和日期，签署 (使用任何 PDF 工具进行数字签名，或打印 → 签署 → 扫描)，保存为 `declaration.pdf`，并将其包含在每次提交中。 如果您无法轻松生成签署的 PDF，也接受纯文本 `declaration.txt`。必需声明 (逐字，不区分大小写)： > *我确认我没有对 `forbidden_frames.txt` 中列出的任何帧进行训练，并且所有已提交的检测都由仅在我生成的合成数据上训练的模型生成。* ## 返回的内容 评分后 (通常对于有效提交花费 < 5 分钟)，您将看到排行榜上的位置以及*详细结果*视图，其中包含所有组件指标，包括每类 AP。

Rules

# 规则 ## 资格要求 - 对所有人开放——研究人员、学生、行业团队。 - 每个团队必须注册一个参赛者账户；不得维护多个账户。 ## 允许的内容 - 任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理引擎）。开源或闭源——重要的是合成数据。 - 任何3D目标检测器架构，仅在**合成数据上**训练。 - 在检测器训练期间应用的增强方法（旋转、缩放、翻转、真值采样、噪声）——这些操作作用于合成数据，而非禁止的真实帧。 - 使用公开真实数据集的**训练集**进行超参数选择或域适应，**前提是不接触任何禁止帧**。（禁止列表仅包含100个预留帧，不包括整个真实训练集。） ## 禁止的内容 - 从`forbidden_frames.txt`中列出的100帧**中的任何一帧**进行训练、验证、超参数调整或以其他方式观察真值标签。这由书面声明强制执行，是挑战赛的基本诚信规则。 - 提交由在任何路边激光雷达数据集的真实标签上训练过的模型生成的预测结果。检测器必须仅在模拟数据上训练。 - 通过Codabench排行榜信号反向工程或推断保留的真实性参考帧（例如，设计用于泄露参考集身份的探测提交）。发现进行此操作的提交将被取消资格。 - 多个账户、子团队账户或跨注册团队协调。 ## 取消资格 组织者保留检查任何提交的合成帧和预测结果的权利，以查找禁止帧泄露的证据（例如，与保留真实帧可疑相似的合成帧；其分布表明接触了保留真值的预测）。被取消资格的参赛者将从排行榜和奖品候选中删除。 ## 奖项 每个赛道：第1名500美元、第2名300美元、第3名200美元。赞助商将在开发阶段开始前公布。 ## 发表和署名 - 每个参赛团队提交一份**4-8页的挑战报告**，描述其方法，截止日期为最后阶段截止时间（2026年11月15日）。 - 倾向于不发表的团队可选择加入其提交的**非发表赛道**。 - 每个赛道前3名团队受邀在2026年IEEE大数据大数据杯研讨会上进行演讲，地点在亚利桑那州凤凰城（2026年12月14-17日），并通过挑战赛相关论文赛道向IEEE BigData 2026论文集提交完整论文。 - 挑战赛组织者可发表所有提交的汇总分析报告（除非获得明确许可，否则匿名）。
