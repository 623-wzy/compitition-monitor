Evaluation

<h1>评估协议</h1> <p> 计算两个得分并组合成一个<em>综合</em>得分，用于决定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合方法：</p> <ol> <li>将50帧提交的合成样本拼接为集合<code>S_syn</code>；将50帧预留的真实参考样本拼接为<code>S_real</code>。</li> <li>将两者掩膜至点云范围<code>[-40, -40, -5, 40, 40, 5]</code>。</li> <li>使用随机种子1234进行均匀随机子采样，每侧保留<strong>N = 10,000个点</strong>（启动工具包中的本地评估器使用相同种子）。</li> <li>在整个10,000点集合上计算<strong>一个</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离 (CD)</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>L2范数最近邻平方距离；对称。数值越低越好。</p> <h3>1b. 最大均值差异 (MMD)</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计量（非对角）。带宽<code>γ</code>通过1,000点联合子样本的中位数启发式设置（<code>γ = 1 / (2 · median ||x - y||²)</code>），以确保核函数在激光雷达空间尺度下不会饱和。数值越低越好。 </p> <h3>1c. 推土机距离 (EMD)</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> 使用欧氏距离作为地面代价的Wasserstein-1距离，通过网络单纯形法（POT的<code>ot.emd2</code>）精确求解。以米为单位报告。数值越低越好。 </p> <h3>1d. Fréchet点云距离 (FPD)</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> 类FID方法：为每个点集拟合三维高斯分布，计算两个高斯分布之间的2-Wasserstein距离。数值越低越好。 </p> <h2>2. 3D目标检测</h2> <p> 参赛者提交在50帧真实激光雷达数据上的检测结果（<code>predictions.json</code>），其真值数据暂不公开。我们在<strong>本赛道定义的8个目标类别</strong>（<em>行人、轿车、自行车、摩托车、公交车、卡车、货车、未知</em>）上计算平均精度，IoU阈值分别取0.5（主要）和0.7（次要）。报告每类AP，<strong>各类别平均AP（mAP）</strong>作为排行榜的检测得分；在预留数据集中真值实例为零的类别不参与平均计算。同时报告KITTI 11点和40点插值AP；40点形式为主要排行榜依据。 </p> <p> 真值和预测框采用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算方式为两个定向鸟瞰图（BEV）矩形的三维交并比乘以Z轴重叠率。不应用KITTI的截断/遮挡/最小高度难度过滤，因为这些依赖于二维边界框标注，而这对路边激光雷达数据集并不自然。 </p> <p>本赛道的有效类别字符串列于<code>config.json</code>（位于<code>reference_data/</code>中）和启动工具包的<code>submission_format.md</code>中。任何类别标签无法识别的预测结果将被丢弃。</p> <h2>3. 综合得分</h2> <p>每个组成部分使用每赛道的归一化范围进行最小-最大归一化至[0, 1]区间：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 → 1 - clip) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 → clip) score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 归一化端点公开于<code>config.json</code>（位于<code>reference_data/</code>中），因此本地评估器和服务器

<h1>数据</h1> <h2>LUMPI</h2> <p> 真实的<strong>LUMPI</strong>数据自其最初发布以来即公开可用。我们不进行再分发。参赛者必须直接从其来源获取真实数据集，并遵守其自有许可协议。 </p> <ul> <li><strong>来源：</strong> <a href="https://data.uni-hannover.de/dataset/lumpi">https://data.uni-hannover.de/dataset/lumpi</a></li> <li><strong>许可协议：</strong> 见来源。</li> </ul> <h2>向参赛者发布的内容</h2> <p>起始工具包（<em>文件</em>标签页 &rarr; starting_kit）包含：</p> <ul> <li><code>detection_test_frames/</code> &mdash; <strong>50个真实LiDAR帧</strong>（仅点云，无标签），您必须在这些数据上运行检测器并提交预测结果。</li> <li><code>detection_test_frame_ids.json</code> &mdash; 您的<code>predictions.json</code>必须按顺序覆盖的帧ID规范列表。</li> <li><code>forbidden_frames.txt</code> &mdash; <strong>100个禁止用于训练、验证或超参数调优的帧ID</strong>。这是50个检测测试帧与50个真实度参考帧的并集。诚信制度，通过在提交时签署声明来执行。</li> <li><code>local_eval.py</code> &mdash; 发送至Codabench工作节点的精确评分程序。在本地运行它，结合您从发布的检测测试帧生成的虚拟参考集，可逐位复现服务器评分。</li> <li><code>make_dummy_submission.py</code> &mdash; 生成一个已知错误的提交，用于测试格式。可用于对您的流程进行健全性检查。</li> <li><code>submission_format.md</code> &mdash; 完整的提交规范。</li> </ul> <h2>保留数据（仅组织者持有）</h2> <ul> <li>50个真实帧，用作<em>真实度参考集</em>。</li> <li>50个检测测试帧的真值框。</li> </ul> <h2>评估类别</h2> <p> 本赛道针对为<strong>LUMPI</strong>数据集定义的<strong>8</strong>个目标类别进行评分：<em>行人、汽车、自行车、摩托车、公交车、卡车、厢式货车、未知</em>。排行榜的检测分数是这些类别的平均AP（平均精度）；在保留的50帧数据集中真值实例数为零的类别不参与平均计算。 </p> <h2>数据划分</h2> <p> 数据划分为分层随机抽样，固定随机种子1234。确切的帧ID列表已发布在起始工具包中，因此任何人都可以从发布的真实数据集中复现这些划分。 </p> <h2>参考基线</h2> <p> 以下数值仅针对<em>汽车</em>类别报告，取自该数据集上的先前工作。排行榜的检测分数是本赛道所有定义类别的平均AP（见<strong>评估</strong>部分），因此提交的评分范围比这些单类别参考更广。纳入这些基线是为了证明在该基准上sim &rarr; real（仿真到真实）迁移是可行的，并为您迭代时提供逐类别的参考基准。 </p> <table border="1" cellpadding="6"> <tr> <th>系统</th><th>汽车3D AP @ 0.5</th><th>汽车3D AP @ 0.7</th> </tr> <tr> <td>SEED（真实LUMPI训练，IEEE T-ITS 2026）</td> <td>0.4270</td> <td>n/r</td> </tr> <tr> <td>SEED（UT-LUMPI合成数据 → 真实LUMPI，IEEE T-ITS 2026）</td> <td>0.4474</td> <td>n/r</td> </tr> </table>

Submission

<h1>提交格式</h1> <p>将以下所有内容打包成单个 <code>submission.zip</code> 文件，并在 <em>提交</em> 标签页上传。</p> <pre> submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好 50 个文件 ├── predictions.json └── declaration.pdf # 签名的诚信声明（PDF）。也接受 declaration.txt。 </pre> <h2>synthetic/&lt;id&gt;.bin</h2> <ul> <li>恰好 <strong>50</strong> 个文件。</li> <li>每个文件为原始 <code>float32</code> 格式，形状 <code>N &times; 3</code>，行优先顺序，通道为 <code>(x, y, z)</code>，单位为米。</li> <li>接受 <code>N &times; 3</code> 或 <code>N &times; 4</code>（xyz + 强度）格式；如果存在强度列，在评分前会被丢弃。</li> <li>每个文件在磁盘上 &le; 1.5 MB（约125,000个点）。真实感在数据集层面计算：所有50帧会被拼接，根据赛道的点云范围进行掩码，然后下采样至10,000个点（随机种子1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会提高分数；帧的顺序无关紧要。</li> <li>最简单的有效命名为 <code>0001.bin … 0050.bin</code>。</li> </ul> <h2>predictions.json</h2> <p>JSON 对象的键为来自 <code>detection_test_frame_ids.json</code>（在起始工具包中）的帧 ID。对于每个帧 ID，必须包含一个条目，即使值为空列表。</p> <pre> { "&lt;frame_id_1&gt;": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "Car"}, {"box": [...], "score": 0.81, "class": "Person"} ], "&lt;frame_id_2&gt;": [], ... } </pre> <ul> <li><code>box</code>：7 个浮点数，遵循 OpenPCDet 约定。<code>(x, y, z)</code> 是边界框在 LiDAR 坐标系中的<em>中心</em>位置（单位：米），<code>(dx, dy, dz)</code> 是沿边界框局部轴的完整尺寸，<code>heading</code> 是绕 <code>+Z</code> 轴的旋转角度（弧度）。</li> <li><code>score</code>：置信度，范围 [0, 1]。</li> <li><code>class</code>：该赛道的有效类别字符串之一。有效值：<code>Person</code>、<code>Car</code>、<code>Bicycle</code>、<code>Motorcycle</code>、<code>Bus</code>、<code>Truck</code>、<code>Van</code>、<code>Unknown</code>。类别字符串不区分大小写进行匹配。包含无法识别类别字符串的预测在计算 AP 之前会被丢弃。</li> </ul> <h2>declaration.pdf（或 declaration.txt）</h2> <p>起始工具包中提供 <code>declaration_template.pdf</code>，这是一份一页的表格，预印了所需的诚信声明和签名栏。填写队伍名称和日期，签名（使用任何 PDF 工具进行数字签名，或打印 &rarr; 签名 &rarr; 扫描），保存为 <code>declaration.pdf</code>，并包含在每次提交中。</p> <p>如果您无法方便地生成签名 PDF，也接受纯文本的 <code>declaration.txt</code>。所需声明（原文照抄，不区分大小写）：</p> <blockquote> <em>我确认未使用 <code>forbidden_frames.txt</code> 中列出的任何帧进行训练，且所有提交的检测结果均由仅使用我生成的合成数据训练的模型产生。</em> </blockquote> <h2>返回内容</h2> <p>评分完成后（有效提交通常在 5 分钟内），您将在排行榜上看到您的排名，以及包含所有 component 指标（包括每类 AP）的<em>详细结果</em>视图。</p>

Rules

<h1>规则</h1> <h2>参赛资格</h2> <ul> <li>面向所有人开放——研究人员、学生、行业团队。</li> <li>每个团队必须注册一个参赛账户；请勿维护多个账户。</li> </ul> <h2>允许事项</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理）。无论开源或闭源——重要的是合成数据。</li> <li>任何三维目标检测器架构，仅使用<em>您的合成数据</em>进行训练。</li> <li>检测器训练期间应用的数据增强（旋转、缩放、翻转、真值采样、噪声）——它们作用于合成数据，而非禁止使用的真实帧。</li> <li>使用公开真实数据集的<strong>训练集划分</strong>进行超参数选择或域自适应，<em>前提是不触碰任何禁止帧</em>。（禁止列表仅包含100个保留帧，而非整个真实训练集划分。）</li> </ul> <h2>禁止事项</h2> <ul> <li>对<code>forbidden_frames.txt</code>中列出的100帧中的<strong>任何</strong>一帧进行训练、验证、超参数调优或以其他方式观测真值。这通过签署声明强制执行，是本次挑战的基础完整性规则。</li> <li>提交使用<em>任何</em>路侧激光雷达数据集的真实标签训练的模型所产生的预测结果。检测器必须仅使用仿真数据。</li> <li>通过Codabench排行榜信号逆向工程或推断保留的真实感参考帧（例如，旨在泄露参考集身份的探测性提交）。发现此类行为的提交将被取消资格。</li> <li>多个账户、子团队账户，或跨注册团队协作。</li> </ul> <h2>取消资格</h2> <p> 组织者保留检查任何提交的合成帧和预测结果的权利，以查找禁止帧泄露的证据（例如，与保留的真实帧惊人相似的合成帧；其分布暗示可访问保留真值的预测）。被取消资格的参与者将从排行榜和奖项评选中移除。 </p> <h2>奖项</h2> <p>每个赛道：第一名500美元，第二名300美元，第三名200美元。赞助商将在开发阶段开始前公布。</p> <h2>发表与署名</h2> <ul> <li>每个参赛团队提交一份<strong>4–8页的挑战报告</strong>，描述其方法，截止日期为最终阶段截止日期（2026年11月15日）。</li> <li>不愿发表的团队可以选择将其提交归入<em>非发表赛道</em>。</li> <li>每个赛道的前三名将获邀在亚利桑那州凤凰城举行的IEEE BigData 2026大数据杯研讨会（2026年12月14日至17日）上进行展示，并可通过挑战赛关联的论文通道向IEEE BigData 2026会议论文集提交完整论文。</li> <li>挑战赛组织者可以发表所有提交的汇总分析（除非获得明确许可，否则将匿名处理）。</li> </ul>
