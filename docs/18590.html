Overview

# 幽门螺杆菌检测挑战赛 **这是UAB内部竞赛。非UAB参与者不予接受。** 欢迎！你的目标是构建一个**检测*幽门螺杆菌***的系统：给定一张256×256的免疫组化染色胃活检组织图像块，你的模型必须返回**该图像块包含幽门螺杆菌的概率**。 ## 运作方式 - 使用**课程公开数据**（Quiron数据集的留出集，仅含患者级诊断）在你自己的计算机上训练模型。 - 提交**代码和训练好的权重**。平台在**专家病理学家标注的隐藏测试集图像块**（你永远看不到）上运行你的模型并给出分数。 - 最高分数将显示在**排行榜**上。 ## 日程安排 | 阶段 | 日期 | 数据 | 提交次数 | |---|---|---|---| | **开发阶段** | 2026年10月11日 – 2026年11月30日（23:59） | 隐藏测试集，**50%**的图像块 | 每天5次 | | **决赛阶段** | 2026年12月1日（09:00） – 2026年12月2日（09:00） | 隐藏测试集，**100%**的图像块 | 总共1次 | - **开发阶段**：用于检查提交是否正常工作以及比较不同想法。基于**一半**隐藏图像块进行评分。 - **决赛阶段**：以此为准。基于**全部**隐藏图像块（开发阶段的一半 + 另一半无人看过的数据）进行评分。最终排名依据你的**唯一一次**决赛提交。 两半数据**按患者**划分：同一患者的所有图像块位于同一半。 ## 规则 - 以班级小组为单位组队参赛。 - 可以使用任何方法：经典计算机视觉、卷积神经网络、自编码器/异常检测、预训练模型等。 - 隐藏图像块不以任何形式提供给参与者。请勿试图获取。

Evaluation

# 评估 每个切片由病理学家给出真实标签：**1** = 存在幽门螺杆菌，**0** = 无幽门螺杆菌。 您的模型为每个切片返回一个 **[0, 1] 范围内的分数**。 ## 排名指标：F1分数 您的分数通过固定阈值转换为决策： **分数 ≥ 0.5 → 阳性（幽门螺杆菌）**，**分数 < 0.5 → 阴性** 然后计算**阳性类别**的F1分数： - **精确率** = TP / (TP + FP) — 在您标记的切片中，真正含有幽门螺杆菌的比例 - **召回率** = TP / (TP + FN) — 在含有幽门螺杆菌的切片中，被您发现的比例 - **F1 = 2 · 精确率 · 召回率 / (精确率 + 召回率)** 排行榜按**F1分数**排名。阳性切片属于少数类别，因此预测"全为阴性"会得到 F1 = 0，预测"全为阳性"也会得到较低的F1。 > 提示：如果您的模型输出的不是校准概率（例如自编码器重构误差），请在验证数据上选择您自己的阈值，并在 `predict()` 内部**将其映射到0.5**。 ## 平局决胜：ROC AUC 如果两支队伍的F1分数相同（保留4位小数），则通过**ROC AUC**决出胜负。它基于您的**原始分数**计算（无需阈值），因此它衡量的是您的分数将阳性切片排在阴性切片之上的能力。仅返回0/1会得到很低的AUC。 ## 其他列 **精确率**和**召回率**仅用于反馈展示，不影响排名。 ## 示例 | 切片 | 真实值 | 分数 | 决策 | |---|---|---|---| | a | 1 | 0.91 | 1 ✅ 真阳性 | | b | 1 | 0.32 | 0 ❌ 假阴性 | | c | 0 | 0.64 | 1 ❌ 假阳性 | | d | 0 | 0.05 | 0 ✅ 真阴性 | 精确率 = 1/2 · 召回率 = 1/2 · **F1 = 0.50** · AUC = 0.75 ## 错误处理 - 如果您的模型在某个切片上**崩溃**，或返回非数字结果，该切片得分为0（阴性）。其余切片仍会被评估。 - [0, 1] 范围外的分数将被截断至 [0, 1]。 - 如果您的提交**完全崩溃**或超出**时间限制**，则提交失败，没有分数。

Submission

# 如何提交 您提交一个包含代码和训练权重的 **.zip 文件**。平台会加载您的模型并在隐藏患者数据上运行。 ## 1. Zip 文件结构 文件必须位于 zip 文件的**根目录**下（不能在文件夹内）： ``` my_submission.zip ├── model.py ← 必需 └── weights/ ← 训练好的模型文件（任意格式） ``` 如果 `model.py` 需要导入其他 `.py` 文件，可以一并添加。 ## 2. `Model` 接口 `model.py` 必须定义一个名为 `Model` 的类，严格遵循以下接口： ```python class Model: def __init__(self, weights_dir: str): # 在此处加载模型（特征提取器 + ABMIL）。 # weights_dir 是 "weights/" 文件夹的路径。 ... def predict(self, patch_paths: list) -> float: # patch_paths：包含某位患者所有 .png 图像块路径的列表 # 返回患者为阳性的概率（0..1），例如 0.87 ... ``` - `predict` 对每个患者调用**一次**，传入该患者的全部图像块集合。 - 图像块是与课程数据集中类似的 **PNG** 图像。每位患者有**数百个图像块**（不同患者的数量差异很大）。 - **并非所有图像块尺寸相同**：大多数是 256×256，但有些不是。**在将图像块堆叠成批次之前，需将每个图像块调整大小（或填充）至固定尺寸**：`np.stack` / `torch.stack` 在处理混合尺寸时会崩溃，而崩溃会导致该患者被判定为阴性。启动套件中的模板（`load_patch`）已包含此功能。 - 在隐藏数据集中，患者文件夹使用**匿名名称**（`P001`、`P002`、…），图像块命名为 `00001.png`、`00002.png`、… - 务必返回 **float** 类型。如果不确定，返回最佳猜测值，而非报错。 - 分数 ≥ 0.5 视为阳性诊断（参见**评估**页面）。 ## 3. 环境 您的代码在固定环境中运行。**无法安装额外包**。 - Python 3.11 - `torch`、`torchvision`（仅 CPU） - `opencv-python-headless`、`numpy`、`pillow` - `scikit-learn`、`scikit-image` 重要限制： - **无 GPU**：在 CPU 上运行模型（`device="cpu"`）。使用 `torch.no_grad()`，并将患者的图像块分批通过特征提取器处理。 - **无网络连接**：所有权重必须包含在 zip 文件内。运行时请勿下载任何内容（例如不要使用 `pretrained=True`：将预训练权重保存在 `weights/` 中）。 - **时间限制**：开发阶段为**3小时**，最终阶段为**4小时**，用于处理整个隐藏数据集（开发阶段：58位患者，约38,000个图像块；最终阶段：58位患者，约50,000个图像块；每位患者约130至7,400个图像块）。作为参考，ResNet18 编码器 + ABMIL 在平台 CPU 上每个图像块耗时约50毫秒（开发阶段约30分钟）。目标是在笔记本电脑 CPU 上**每个图像块耗时<200毫秒**（包括读取图像）。 - **内存**：部分患者有超过7,000个图像块。请勿将患者的所有图像加载到一个张量中：分批（例如64个图像块）读取和编码，仅保留特征。 - 将 zip 文件大小控制在**600 MB以内**（代码+权重）。较小的 zip 文件上传和启动更快。 ## 4. 先进行本地测试！ 您**无法查看**最终提交的日志，因此如果出错，您将无法得知原因。提交前务必使用提供的 `run_local.py` 脚本（在**启动套件**中）进行测试。 将一些**未用于训练**的患者数据放入一个文件夹中，每位患者一个子文件夹： ``` my_val/ ├── B22-25_0/ ← 该患者的 .png 图像块 ├── B22-31_0/ ├── ... └── labels.csv ← 可选：真实标签（患者,标签） ``` `labels.csv`（可选）必须有表头，每行一位患者，`1` 表示阳性，`0` 表示阴性： ``` patient,label B22-25_0,1 B22-31_0,0 ``` ### 运行 ```bash python run_local.py --submission my_submission.zip --data my_val/ ``` 它会检查您的 zip 文件结构，像平台一样加载模型，并输出 F1（10次采样及所有患者上的均值±标准差）、ROC AUC、精确率、召回率以及每位患者的耗时。
