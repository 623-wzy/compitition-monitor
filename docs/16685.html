background:#fff8e6; padding:10px 14px; margin:0 0 18px;"> <strong>更新——</strong><strong>意向书截止日期已延长至2026年8月15日</strong> （之前为7月25日）。所有其他日期保持不变。 </p> <p><em>2026 IEEE大数据杯的一个赛道，与<a href="https://bigdataieee.org/BigData2026/">2026 IEEE国际大数据会议（IEEE BigData 2026）、美国亚利桑那州凤凰城</a>联合举办。</em></p> <p> 智能交通系统中的路侧激光雷达感知面临的瓶颈是缺乏成本高昂且稀缺的大规模、高质量标注真实数据集。本挑战赛提出的问题是：能否使合成激光雷达数据足够逼真，使得在其上训练的深度学习模型能够泛化到真实激光雷达帧？ </p> <p> 为此，本挑战赛要求参赛者生成针对<strong>V2X-Real</strong> 分布的合成激光雷达数据，在该数据上训练目标检测器，并在真实保留帧上提交检测结果。评分基于以下两个方面：（1）其合成帧与真实帧的分布接近程度，以及（2）仅基于合成数据训练的检测器在真实帧上的性能。 </p> <h2>重要日期</h2> <ul> <li><strong>意向书截止日期：</strong><strong>2026年8月15日</strong>（从7月25日延长）</li> <li><strong>最终报告和方案提交截止日期：</strong>2026年11月15日</li> <li><strong>获奖队伍公布：</strong>2026年11月25日</li> <li><strong>会议时间：</strong>2026年12月14日至17日</li> </ul> <h2>参赛者参考资源</h2> <p> 为支持希望获得有文档记录起点的参赛者，我们公开提供了完整的参考管道，涵盖合成方法、实证分析、即用型合成数据集以及开源激光雷达数据处理和可视化软件。这些材料仅供参考，不作为强制要求。 </p> <p> 合成管道详见<a href="https://arxiv.org/pdf/2509.02903">UrbanTwin：为Sim2Real激光雷达感知和评估构建高保真数字孪生（arXiv预印本）</a>，其中包含更深入的实证分析，包括本挑战赛采用的分布现实性度量，详见<a href="https://scholar.google.com/scholar?oi=bibs&amp;cluster=6844982498826808010&amp;btnI=1&amp;hl=en">高保真数字孪生：弥合激光雷达智能交通感知中的Sim2Real差距（IEEE T-ITS, 2026）</a>。 </p> <p> 使用该管道生成的合成激光雷达数据集发表于<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">UrbanTwin：合成路侧激光雷达数据集（IEEE OJ-ITS, 2026）</a>，可从<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">哈佛数据库</a>下载。每个数据集包含<strong>10,000帧</strong>，涵盖<strong>六个对象类别</strong>的标注，用于<strong>检测、跟踪和分割任务</strong>，与本挑战赛使用的多类评估直接兼容；论文中的实证分析包括分布现实性度量和单类3D目标检测研究作为概念验证。对于端到端激光雷达处理，我们还提供了<a href="https://ieeexplore.ieee.org/document/11498694">LiGuard框架（IEEE T-IV, 2026）</a>

Evaluation

<h1>评估协议</h1> <p> 计算两个得分并将其合并为单一<em>综合</em>得分，该得分决定排行榜排名。 </p> <h2>1. 分布逼真度</h2> <p>聚合方法：</p> <ol> <li>将50个提交的合成帧连接到一个集合<code>S_syn</code>中；将50个保留的真实参考帧连接到<code>S_real</code>中。</li> <li>将两者掩膜到点云范围<code>[-40, -40, -8, 40, 40, 2]</code>。</li> <li>以种子1234均匀随机子采样到每侧<strong>N = 10,000个点</strong>（与启动工具包中的本地评估器使用的种子相同）。</li> <li>计算整个10,000个点集合上的<strong>一个</strong>CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离 (CD)</h3> <pre> CD(P, Q) = (1/|P|) Σ_{p ∈ P} min_{q ∈ Q} ||p - q||² + (1/|Q|) Σ_{q ∈ Q} min_{p ∈ P} ||p - q||² </pre> <p>平方L2最近邻成本；对称。越低越好。</p> <h3>1b. 最大平均差异 (MMD)</h3> <pre> MMD²(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-γ ||a - b||²) </pre> <p> 无偏估计器（非对角线）。带宽<code>γ</code>由1000点联合子样本的中位数启发式法则设置（<code>γ = 1 / (2 · median ||x - y||²)</code>），以确保核在激光雷达空间尺度下不饱和。越低越好。 </p> <h3>1c. 地球移动距离 (EMD)</h3> <pre> EMD(X, Y) = √ ( min_{T ∈ Π(X, Y)} Σ_{i,j} T_{ij} · ||x_i - y_j|| ) </pre> <p> Wasserstein-1距离，使用欧氏距离作为基础成本，由网络单纯形精确求解（POT的<code>ot.emd2</code>）。以米为单位报告。越低越好。 </p> <h3>1d. Fréchet点云距离 (FPD)</h3> <pre> FPD = ||μ_X - μ_Y||² + Tr(Σ_X + Σ_Y - 2 (Σ_X · Σ_Y)^{1/2}) </pre> <p> FID风格：为每个集合的点拟合3元高斯分布，计算两个高斯之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 3D物体检测</h2> <p> 参赛者在50个真实激光雷达帧上提交检测结果（<code>predictions.json</code>），这些帧的真实标注被保留。我们在本赛道定义的<strong>3个物体类别</strong>（<em>车辆、行人、卡车</em>）上计算平均精度，IoU阈值分别为0.5（主要）和0.7（次要）。报告逐类AP，并将<strong>类别间平均AP（mAP）</strong>作为排行榜的检测得分；保留集中零真实标注实例的类别被排除在平均值外。报告KITTI 11点和40点插值AP两种形式；40点形式是排行榜主要形式。 </p> <p> 真实标注框和预测框使用OpenPCDet 7自由度格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个有向BEV矩形的3D交并比乘以Z重叠度。由于KITTI的截断/遮挡/最小高度难度过滤依赖于不是路边激光雷达数据集自然属性的2D边界框标注，因此不应用该过滤。 </p> <p>本赛道的有效类别字符串列在<code>config.json</code>中（包含在<code>reference_data/</code>中）以及启动工具包中的<code>submission_format.md</code>中。任何带有无法识别的类别标签的预测都将被丢弃。</p> <h2>3. 综合得分</h2> <p>使用每个赛道的归一化范围，将每个组成部分最大-最小归一化到[0, 1]：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 → 1 - clip) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 → clip) score_combined = 0.6 · score_detection + 0.4 · score_realism </pre> <p> 归一化端点在<code>config.json</code>中公开（包含在<code>reference_data/</code>中），因此本地评估器和服务器计算相同的得分。 </p>

Data

# 数据 ## V2X-Real 真实的 **V2X-Real** 数据可从其原始发布源公开获取。我们不进行重新分发。参赛者必须根据其许可证直接从源获取真实数据集。 <ul> <li><strong>来源：</strong> <a href="https://github.com/ucla-mobility/V2X-Real">https://github.com/ucla-mobility/V2X-Real</a></li> <li><strong>许可证：</strong> 见源。</li> </ul> ## 为参赛者发布的文件 起始工具包（*Files* 标签 → starting_kit）包含： <ul> <li><code>detection_test_frames/</code> — **50 帧真实激光雷达点云**（仅点云，无标签），您必须在其上运行检测器并提交预测结果。</li> <li><code>detection_test_frame_ids.json</code> — 您的 <code>predictions.json</code> 必须按顺序覆盖的规范帧 ID 列表。</li> <li><code>forbidden_frames.txt</code> — **100 个禁止用于训练、验证或超参数调整的帧 ID**。这是 50 个检测测试帧和 50 个真实性参考帧的并集。基于荣誉制度，由您提交中的签署声明强制执行。</li> <li><code>local_eval.py</code> — 与 Codabench worker 一致的精确评分程序。在本地运行以重现服务器分数（位级准确），给定您从已发布检测测试帧生成的虚拟参考集。</li> <li><code>make_dummy_submission.py</code> — 生成一个已知的不良提交以验证格式。对于健全性检查您的流程很有用。</li> <li><code>submission_format.md</code> — 完整提交规范。</li> </ul> ## 保留（仅组织者可见） <ul> <li>用作*真实性参考集*的 50 帧真实帧。</li> <li>50 帧检测测试帧的真实标注框。</li> </ul> ## 评估类别 本赛道根据 **V2X-Real** 数据集定义的 **3** 个物体类别进行评分：*车辆、行人、卡车*。排行榜的检测分数是这些类别中平均 AP；在保留的 50 帧集中地真实实例为零的类别会从平均值中排除。 ## 数据集划分 划分是使用固定种子 1234 的分层随机样本。精确的帧 ID 列表在起始工具包中发布，因此任何人都可以从已发布的真实数据集中复现它们。 ## 参考基线 下面的数字仅针对*车*类报告，来自该数据集的先前工作。排行榜的检测分数是本赛道所有定义类别中平均 AP 的平均值（见**评估**），因此提交的评分范围比这些单类参考更广。包含基线是为了证明 sim → real 迁移在该基准上是可行的，并在您迭代时提供按类参考点用于定向。 | 系统 | 车 3D AP @ 0.5 | 车 3D AP @ 0.7 | |------|---|---| | V2X-Real 无融合基准（SECOND，真实） | 0.3556 | n/r | | SECOND（UT-V2X-Real 合成 → V2X-Real-IC，IEEE T-ITS 2026） | 0.6318 | n/r |

Submission

# 提交格式 将下列所有内容打包到单个 `submission.zip` 文件中，在*提交*标签页上传。 ``` submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好 50 个文件 ├── predictions.json └── declaration.pdf # 签署的荣誉声明（PDF 格式）。也接受 declaration.txt ``` ## synthetic/<id>.bin - 恰好 **50** 个文件。 - 每个文件为原始 `float32` 格式，形状为 `N × 3`，按行主序排列，通道为 `(x, y, z)`（单位：米）。 - 接受 `N × 3` 或 `N × 4` 格式（xyz + 强度）；若存在强度列，评分前将被丢弃。 - 每个文件 ≤ 1.5 MB（约 125,000 个点）。真实度在数据集级别计算：将全部 50 帧连接，掩码到轨迹的点云范围，然后子采样到 10,000 个点（种子 1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会改善评分；帧顺序无关紧要。 - 最简单的有效命名为 `0001.bin … 0050.bin`。 ## predictions.json JSON 对象，其键为 `detection_test_frame_ids.json`（在启动工具包中）中的帧 ID。对于每个帧 ID，必须包含一个条目，即使值为空列表。 ```json { "<frame_id_1>": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "vehicle"}, {"box": [...], "score": 0.81, "class": "pedestrian"} ], "<frame_id_2>": [], ... } ``` - `box`：7 个浮点数，遵循 OpenPCDet 约定。`(x, y, z)` 为 LiDAR 坐标系中的框*中心*（单位：米），`(dx, dy, dz)` 为沿框局部轴的完整范围，`heading` 为绕 `+Z` 轴的旋转角度（单位：弧度）。 - `score`：置信度，范围 [0, 1]。 - `class`：该轨迹的有效类别字符串之一。有效值：`vehicle`、`pedestrian`、`truck`。类别字符串匹配不区分大小写。计算 AP 前，无法识别的类别字符串预测将被丢弃。 ## declaration.pdf（或 declaration.txt） 启动工具包包含 `declaration_template.pdf`，一个单页表单，必需的荣誉声明已预印，并有签名行。填写团队名称和日期，签署（使用任何 PDF 工具数字签署，或打印 → 签署 → 扫描），另存为 `declaration.pdf`，并将其包含在每次提交中。 如果无法轻松生成签署的 PDF，也接受纯文本 `declaration.txt`。所需声明（逐字，不区分大小写）： > *我确认我没有在 `forbidden_frames.txt` 中列出的任何帧上进行训练，并且所有提交的检测均由仅在我生成的合成数据上训练的模型生成。* ## 返回内容 评分后（通常对有效提交耗时不到 5 分钟），您将在排行榜上看到您的位置，以及一个*详细结果*视图，包含所有组件指标（包括按类别的 AP）。

Rules

<h1>规则</h1> <h2>资格要求</h2> <ul> <li>对所有人开放——研究人员、学生、行业团队。</li> <li>每个团队必须注册一个参赛者账户；不得维护多个账户。</li> </ul> <h2>允许的做法</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、生成对抗网络、自定义物理）。开源或闭源均可——重要的是合成数据。</li> <li>任何3D目标检测器架构，仅在<em>你的合成数据</em>上训练。</li> <li>检测器训练过程中应用的增强方法（旋转、缩放、翻转、真值采样、噪声）——这些操作作用于合成数据，而非禁用的真实帧。</li> <li>使用公开真实数据集的<strong>训练集</strong>进行超参数选择或域适应，<em>前提是不涉及任何禁用帧</em>。（禁用列表仅包含100个预留帧，不是整个真实训练集。）</li> </ul> <h2>禁止的做法</h2> <ul> <li>从<code>forbidden_frames.txt</code>中列出的<strong>任何</strong>100个帧进行训练、验证、超参数调优或观察真值标签。这通过签署声明强制执行，是本挑战赛的基础完整性规则。</li> <li>提交由在任何路边激光雷达数据集上用真实标签训练过的模型生成的预测。检测器必须仅在模拟数据上训练。</li> <li>反向工程或通过Codabench排行榜信号推断隐藏的真实性参考帧（例如设计用于泄露参考集身份的探测性提交）。发现进行此操作的提交将被取消资格。</li> <li>多个账户、子团队账户或在已注册团队间进行协调。</li> </ul> <h2>取消资格</h2> <p> 组织者保留检查任何提交的合成帧和预测的权利，以查证是否存在禁用帧泄露的证据（例如，与隐藏真实帧可疑相似的合成帧；其分布表明能获取隐藏真值的预测）。被取消资格的参赛者将被移出排行榜和奖项考虑范围。 </p> <h2>奖项</h2> <p>各赛道：第一名500美元、第二名300美元、第三名200美元。赞助商将在开发阶段开始前公布。</p> <h2>发表与署名</h2> <ul> <li>每个参赛团队需提交一份<strong>4至8页的挑战赛报告</strong>，描述其方法，截止日期为最终阶段截止日（2026年11月15日）。</li> <li>不愿发表的团队可选择其提交的<em>非发表赛道</em>。</li> <li>各赛道前三名团队受邀在IEEE BigData 2026 Big Data Cup研讨会（亚利桑那州凤凰城，2026年12月14-17日）上进行演讲，并通过挑战赛相关论文渠道向IEEE BigData 2026论文集投稿完整论文。</li> <li>挑战赛组织者可发表所有提交的汇总分析（除非明确授权，否则匿名处理）。</li> </ul>
