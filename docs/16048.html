Overview

# UrbanTwin Sim2Real LiDAR挑战赛 — V2X-Real赛道 *6th DriveX Workshop @ ECCV 2026的挑战赛道 — <a href="https://drivex-workshop.github.io/eccv2026">drivex-workshop.github.io/eccv2026</a>。* 路侧LiDAR感知在智能交通系统中的发展受到了大规模、高质量标注真实数据成本高昂且稀缺的限制。本挑战赛提出问题：合成LiDAR数据是否能够足够逼真，使得在其上训练的深度学习模型能够泛化到真实LiDAR帧？ 为此，本挑战赛要求参赛者生成自己的合成LiDAR数据以匹配**V2X-Real**分布，在该数据上训练目标检测器，并提交对真实保留测试集帧的检测结果。评分基于：(1)其合成帧与真实帧的分布接近程度，以及(2)仅在合成数据上训练的检测器在真实帧上的性能。 ## 参赛者参考资源 为支持需要有据可查的起点的参赛者，我们公开提供了一整套完整参考管道，涵盖合成方法论、实证分析、即用型合成数据集，以及开源LiDAR数据处理和可视化软件。这些资料作为参考方向提供，不作为强制要求。 合成管道详见<a href="https://arxiv.org/pdf/2509.02903">UrbanTwin: Building High-Fidelity Digital Twins for Sim2Real LiDAR Perception and Evaluation（arXiv预印本）</a>，更深入的实证分析包括本挑战赛采用的分布真实性指标详见<a href="https://scholar.google.com/scholar?oi=bibs&cluster=6844982498826808010&btnI=1&hl=en">High-Fidelity Digital Twins for Bridging the Sim2Real Gap in LiDAR-Based ITS Perception（IEEE T-ITS，2026）</a>。 使用该管道生成的合成LiDAR数据集发布在<a href="https://ieeexplore.ieee.org/iel8/8784355/8957420/11357520.pdf">UrbanTwin: Synthetic Roadside LiDAR Datasets（IEEE OJ-ITS，2026）</a>，可在<a href="https://dataverse.harvard.edu/dataverse/ucf-ut">Harvard Dataverse</a>下载。每个数据集包含**10K帧**，标注涵盖**六个物体类别**，支持**检测、跟踪和分割任务**，与本挑战赛采用的多类别评估直接兼容；论文中的实证分析包括分布真实性指标和单类别3D物体检测概念验证研究。对于端到端LiDAR处理，我们还提供<a href="https://ieeexplore.ieee.org/document/11498694">LiGuard框架（IEEE T-IV，2026）</a>，以及更简洁的软件相关阅读<a href="https://joss.theoj.org/papers/10.21105/joss.06751.pdf">《开源软件期刊》</a>。 ## 你将要做的事 1. 下载公开的真实**V2X-Real**数据集和已发布的检测测试点云（50个真实帧，无标签）。 2. 使用任何方法生成合成LiDAR帧——模拟（CARLA、LGSVL、自定义）、生成模型（扩散、GAN、基于流的模型）、混合管道或其他任何方法。 3. **仅在你的合成数据**上训练3D物体检测器（任何架构）。 4. 提交： - 50个你的合成LiDAR帧 - 你的检测器对50个已发布测试点云的预测结果 - 一份签署的诚信声明 ## 评分概览 综合得分 = `0.6 × 归一化3D mAP` + `0.4 × 归一化真实性`，其中3D mAP在本赛道定义的**3个**物体类别（*车辆、行人、卡车*）上求平均，真实性对归一化倒角距离、最大均值差异、地球移动距离和Fréchet点云距离求平均

Evaluation

# 评估协议 <p> 计算两个分数并将其合并为单一的<em>综合</em>分数，该分数决定排行榜排名。 </p> <h2>1. 分布真实性</h2> <p>聚合：</p> <ol> <li>将50帧提交的合成帧连接成一个集合<code>S_syn</code>；将50帧保留的真实参考帧连接成<code>S_real</code>。</li> <li>将两者掩码到点云范围<code>[-40, -40, -8, 40, 40, 2]</code>。</li> <li>以均匀随机方式以<strong>每侧N = 10,000个点</strong>进行下采样，种子值为1234（与启动工具包中的本地评估器使用的种子相同）。</li> <li>在整个10,000个点的集合上计算<strong>一个</strong> CD、MMD、EMD和FPD。</li> </ol> <h3>1a. 倒角距离（CD）</h3> <pre> CD(P, Q) = (1/|P|) &Sigma;_{p &isin; P} min_{q &isin; Q} ||p - q||&sup2; + (1/|Q|) &Sigma;_{q &isin; Q} min_{p &isin; P} ||p - q||&sup2; </pre> <p>平方L2最近邻成本；对称。越低越好。</p> <h3>1b. 最大平均差异（MMD）</h3> <pre> MMD&sup2;(X, Y) = E[k(x, x')] + E[k(y, y')] - 2 E[k(x, y)], k(a, b) = exp(-&gamma; ||a - b||&sup2;) </pre> <p> 无偏估计量（非对角线）。带宽<code>&gamma;</code>由1,000个点的联合子样本上的中位数启发式设置（<code>&gamma; = 1 / (2 &middot; median ||x - y||&sup2;)</code>），使核在激光雷达空间尺度不会饱和。越低越好。 </p> <h3>1c. 地球搬运距离（EMD）</h3> <pre> EMD(X, Y) = &radic; ( min_{T &isin; &Pi;(X, Y)} &Sigma;_{i,j} T_{ij} &middot; ||x_i - y_j|| ) </pre> <p> Wasserstein-1距离，欧几里得地面成本，由网络单纯形精确求解（POT的<code>ot.emd2</code>）。以米为单位报告。越低越好。 </p> <h3>1d. Fréchet点云距离（FPD）</h3> <pre> FPD = ||&mu;_X - &mu;_Y||&sup2; + Tr(&Sigma;_X + &Sigma;_Y - 2 (&Sigma;_X &middot; &Sigma;_Y)^{1/2}) </pre> <p> FID风格：对每个集合的点拟合3变量高斯分布，计算高斯分布之间的2-Wasserstein距离。越低越好。 </p> <h2>2. 三维物体检测</h2> <p> 参赛者在50帧真实激光雷达帧上提交检测结果（<code>predictions.json</code>），这些帧的真实标签被保留。我们计算在<strong>本赛道定义的3个物体类别</strong>（<em>车辆、行人、卡车</em>）上的平均精度，IoU阈值为0.5（主要）和0.7（次要）。报告按类别的AP，<strong>类别间的平均AP（mAP）</strong>是排行榜的检测分数；保留集中真实标签数为零的类别被排除在平均值外。报告KITTI 11点和40点插值AP；40点形式是排行榜的主要指标。 </p> <p> 真实标签和预测框使用OpenPCDet 7-DoF格式<code>[x, y, z, dx, dy, dz, heading]</code>。IoU计算为两个有向BEV矩形的三维交并比乘以Z重叠。未应用KITTI截断/遮挡/最小高度难度过滤，因为这些取决于对于路边激光雷达数据集不自然的二维边界框注释。 </p> <p>本赛道的有效类别字符串列在<code>config.json</code>中（在<code>reference_data/</code>中提供）和启动工具包中的<code>submission_format.md</code>中。任何具有无法识别的类别标签的预测都将被丢弃。</p> <h2>3. 综合分数</h2> <p>每个组件使用按赛道的归一化范围被最小-最大归一化到[0, 1]：</p> <pre> score_realism = mean( norm(CD), norm(MMD), norm(EMD), norm(FPD) ) (越低越好 &rarr; 1 - clip) score_detection = norm( AP_3d @ IoU 0.5 ) (越高越好 &rarr; clip) score_combined = 0.6 &middot; score_detection + 0.4 &middot; score_realism </pre> <p> 归一化端点在<code>config.json</code>中公开（在<code>reference_data/</code>中提供），因此本地评估器和服务器计算相同的分数。 </p>

Submission

# 提交格式 将以下所有内容打包到单个 `submission.zip` 中，然后在*提交*标签页上传。 ``` submission.zip ├── synthetic/ │ ├── 0001.bin │ ├── 0002.bin │ ├── ... │ └── 0050.bin # 恰好50个文件 ├── predictions.json └── declaration.pdf # 签署的荣誉声明（PDF）。也接受 declaration.txt。 ``` ## synthetic/<id>.bin - 恰好 **50** 个文件。 - 每个文件为原始 `float32` 格式，形状为 `N × 3`，按行主序存储，通道为 `(x, y, z)`（单位：米）。 - 接受 `N × 3` 或 `N × 4`（xyz + 强度）格式；若存在强度列，计分前会将其丢弃。 - 每个文件 ≤ 1.5 MB（约 125,000 个点）。真实感在数据集级别计算：将所有 50 帧连接，遮罩到轨迹的点云范围，然后下采样到 10,000 个点（种子 1234），再计算 CD / MMD / EMD / FPD。提交更密集的帧不会改善分数；帧顺序无关。 - 最简单的有效命名为 `0001.bin … 0050.bin`。 ## predictions.json JSON 对象，其键为 `detection_test_frame_ids.json`（在初始工具包中）中的帧 ID。对每个帧 ID 必须包含一个条目，即使值为空列表也是如此。 ``` { "<frame_id_1>": [ {"box": [x, y, z, dx, dy, dz, heading], "score": 0.97, "class": "vehicle"}, {"box": [...], "score": 0.81, "class": "pedestrian"} ], "<frame_id_2>": [], ... } ``` - `box`：7 个浮点数，遵循 OpenPCDet 规范。`(x, y, z)` 是盒子*中心*在 LiDAR 坐标系中的位置（单位：米），`(dx, dy, dz)` 是沿盒子局部轴的完整尺寸，`heading` 是围绕 `+Z` 的旋转（单位：弧度）。 - `score`：置信度，范围 [0, 1]。 - `class`：此轨迹的有效类别字符串之一。有效值：`vehicle`（车辆）、`pedestrian`（行人）、`truck`（卡车）。类别字符串匹配不区分大小写。计算 AP 前会丢弃具有无法识别类别字符串的预测。 ## declaration.pdf（或 declaration.txt） 初始工具包包含 `declaration_template.pdf`，这是一份单页表单，具有预先打印的必需荣誉声明和签名行。填入团队名称和日期，签署（使用任何 PDF 工具进行数字签名，或打印 → 签署 → 扫描），另存为 `declaration.pdf`，并将其包含在每次提交中。 如果无法轻松生成签署的 PDF，也接受纯文本 `declaration.txt`。必需声明（逐字，不区分大小写）： > *我确认我没有对 `forbidden_frames.txt` 中列出的任何帧进行训练，且所有提交的检测都是由仅在我生成的合成数据上训练的模型生成的。* ## 返回内容 评分后（有效提交通常 < 5 分钟），您将在排行榜上看到您的位置，以及包含所有组件指标的*详细结果*视图，包括按类别的 AP。

Rules

<h1>规则</h1> <h2>参赛资格</h2> <ul> <li>面向所有人开放——研究人员、学生、产业团队均可参赛。</li> <li>每个团队必须注册一个参赛者账户，不得维持多个账户。</li> </ul> <h2>允许的内容</h2> <ul> <li>任何仿真框架或生成模型（CARLA、Helios++、OpenScene、神经辐射场、扩散模型、GAN、自定义物理引擎）。开源或闭源均可——重要的是合成数据的质量。</li> <li>任何3D目标检测器架构，仅在<em>你自己生成的合成数据</em>上训练。</li> <li>检测器训练过程中应用的数据增强（旋转、缩放、翻转、真值采样、噪声）——这些操作作用于合成数据，而非禁止的真实图像。</li> <li>使用公共真实数据集的<strong>训练集</strong>进行超参数选择或域适应，<em>条件是不接触任何禁止的图像</em>。（禁止列表仅包含100个保留帧，不包括整个真实训练集。）</li> </ul> <h2>禁止的内容</h2> <ul> <li>对<code>forbidden_frames.txt</code>中列出的任何100帧进行训练、验证、超参数调整或以其他方式观察其真值标注。这由签署声明强制执行，是本挑战赛的基础完整性规则。</li> <li>提交由在任何路侧激光雷达数据集的真实标签上训练过的模型所生成的预测结果。检测器必须仅基于仿真数据。</li> <li>通过Codabench排行榜信号逆向工程或推断被保留的真实参考帧（例如，设计用于泄露参考集身份的探测性提交）。发现进行此操作的提交将被取消资格。</li> <li>多个账户、子团队账户或已注册团队间的协调。</li> </ul> <h2>取消资格</h2> <p> 组织者保留权利检查任何提交的合成图像和预测结果，以寻找禁止帧泄露的证据（例如，与被保留真实图像可疑相似的合成帧；其分布暗示获得了被保留真值标注的预测）。被取消资格的参赛者将从排行榜和奖项考虑中被移除。 </p> <h2>奖金</h2> <p>每个赛道：第1名USD 500，第2名USD 300，第3名USD 200。赞助商信息将在开发阶段开始前公布。</p> <h2>发表与署名</h2> <ul> <li>每支参赛团队提交一份<strong>4–8页的挑战赛报告</strong>，描述其方法。</li> <li>不愿发表的团队可选择参加研讨会的<em>非发表赛道</em>。</li> <li>每个赛道的前3名团队另外邀请向<em>下一届DriveX研讨会论文集赛道</em>提交完整论文。</li> <li>挑战赛组织者可发表所有提交的汇总分析（匿名处理，除非获得明确授权）。</li> </ul>
